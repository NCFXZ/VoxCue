**应该保留的设计**

- 以聊天作为准备入口，资料按需展开，主导航保持简单。
- 开始面试前核对设备和权限；本场配置确认后锁定，自动回答仍可切换。
- 转写按面试官与面试者区分，记录可以双向定位问题与回答。
- 删除对话明确展示对象、不可恢复提示，并默认聚焦取消；本次实际确认焦点为取消。
- Markdown、表格、代码复制、公开摘要折叠，以及阅读旧内容时停止跟随滚动。
- 沿用当前毛玻璃和轻量视觉，不需要为本轮改进引入 Liquid Glass 或新装饰风格。

**视觉调整建议**

优先增加文字的可读性，而不是整体放大留白。主聊天可保持目前约 740px 的最大阅读宽度；正文与记录正文使用接近的字号层级。表单标签、说明、错误与按钮需要形成稳定的阅读顺序。浅色次级文本应加深，深色现有次级颜色对主背景约 6.09:1，可以保留其基本方向。

常用图标按钮建议保留 32px 以上点击区；输入框中目前约 26px 的工具按钮可适度增加热区，保持图标尺寸紧凑。这个建议是为了提高操作容错，不能仅凭 26px 就判定违反无障碍标准。选中状态、悬停状态与禁用状态应分别可辨，重要状态不能只依赖颜色。

普通文本 4.5:1 的参照来自 [W3C 对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。点击区还应结合相邻距离与例外条件评估，参照 [W3C 目标尺寸说明](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)。本次没有进行完整无障碍合规认证。

**实施顺序**

1. 先修正保存与发送范围文案、个人信息未保存草稿、对话草稿归属及核心文字对比度。
2. 再缩短开场设置路径，完善 AI 取消与失败恢复、浮窗状态和新结果定位。
3. 然后整理资料入口、知识库普通视图、窄窗辅助面板和记录搜索。
4. 最后统一图标语义、语言、品牌密度和键盘细节；键盘缺陷若阻碍核心任务，应提前处理。

每一组修改保持小范围回归，不把所有界面重写为一次改版。语音准确率、模型响应质量与 UI 可用性分别验收，删除未达标功能不能代替质量改善。
