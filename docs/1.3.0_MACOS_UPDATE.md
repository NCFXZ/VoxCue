# VoxCue 1.3.0 macOS 开发交接

对照对象是正式的 Apple Silicon 1.2.3（`macos-v1.2.3`、`4fe22ec`）与本轮 Windows 开发实现。两端共用 `shared/`，Mac 专属适配仍以本机源码和签名产物验收。文中的“共享”表示代码已接入公共路径，“待接”表示 Mac 尚缺实现。所有 Mac 验收均待在本机执行。当前发行状态见[项目进度](../PROGRESS.md)，Windows 逐项依据见[Windows 更新日志](1.3.0_WINDOWS_UPDATE.md)、[Windows 开发交接](../shared/docs/WINDOWS_1.3.0_HANDOFF.md)。

## 在 Mac 上的实施顺序

1. **建立可构建的基线。** 先检查 `git status --short --branch`、本轮差异及未跟踪文件。按正式 Mac 标签辨认已发行行为。窄窗记录标题按钮换行与回答数单复数在 Mac 1.2.3 已交付。冻结 v1/v11 凭据助手和固定签名身份按原流程恢复。仓库根运行 `pnpm sync:workspace`，核对 Mac 的 package.json、三份 tsconfig、vite.config.mjs 和 pnpm-workspace.yaml，依赖只装在 `macos/`。检查 `pnpm check:workspace`、`pnpm check:architecture`。补齐下一项的平台图标后运行 `pnpm typecheck` 和共享构建。[已有基线](../shared/docs/MACOS_1.2.3_RELEASE.md) · [配置生成](../shared/scripts/sync-platform-manifests.mjs)
2. **先补图标。** 共享 Vite 将图标模块替换为 `macos/src/icons.tsx`，Mac 当前缺十个静态导出 `ArrowRightLeft`、`LinkOff`、`CloudOffline`、`Pause`、`Locate`、`VisibleWindow`、`PrivateWindow`、`Minimize`、`BackTen`、`ForwardTen`。另需动态查找的 `Eye`、`EyeOff`，否则密码显隐退为文字。更新 Mac 符号清单及导出，在 `macos/` 依次运行 `pnpm build:symbols`、`pnpm build:shared`、`pnpm test:icons`。逐页检验 SF Symbols 在支持的系统上可生成、带正确无障碍名称。[Mac 图标接口](../macos/src/icons.tsx) · [符号映射](../macos/src/symbols.json) · [生成工具](../macos/scripts/build-symbols.mjs)
3. **接原生端口，再通业务。** 完成安全密钥输入与钥匙串维护、Core Audio 分流、独立 Silero 资源和受信证书预配。并行修订 Mac 面试选模、音频和归档夹具。再做窗口、多屏截图、Lance 检索、组件安装与更新恢复验证。[平台装配](../macos/electron/platform.ts) · [平台接口](../shared/electron/platform/types.ts)
4. **最后走正式 1.2.3 升级与签名包。** 开发态的类型、共享测试或局部 ASAR 通过，只覆盖各自路径。由 Mac 的隔离 guest 运行最终签名包。在已登录且解锁的控制台串行运行各 GUI/原生专项。使用合成账户、临时资料、专用测试钥匙串及核验摘要的公开模型和音频。[Mac guest 入口](../macos/docs/TEST_GUEST.md)

在最终签名 `.app` 及其更新 ZIP 中，分别核对 `Contents/Resources/app.asar` 和同级的物理解包目录 `app.asar.unpacked`。

- **旧版自定义快捷键。** 现有 Mac 升级夹具的资料快照没有读取快捷键。用正式 1.2.3 将「显示或隐藏面试窗口」改为 `Control+Alt+K`，记录全部九项绑定；在升级后的 1.3.0 及其首次冷重启分别检查九项原值和新增的「显示或隐藏快捷键说明」默认值 `Control+Shift+/`。从浮窗实际触发两项操作。[现有 Mac 升级夹具](../macos/test/scripts/package-upgrade-data.mjs) · [共享快捷键契约](../shared/electron/contracts/shortcuts.ts)
- **渲染器与 Worker。** 从 `dist/.vite/manifest.json` 核对桌面、手机的 HTML 入口及其模块、CSS 和公开资源。桌面模块中 `new Worker(new URL(...))` 引用的 `cloudRecordJson.worker-<哈希>.js` 可能没有独立的 manifest 项，应沿模块实际引用找到文件。逐项核对包内文件和构建输出字节，再从签名应用恢复一条正文超过 8 MiB 的合成云记录，核对 Worker 从包内加载并提交记录。[包组装](../macos/scripts/package-app.mjs) · [云记录解析](../shared/src/services/cloudData.ts) · [Windows 资源核对参考](../windows/test/scripts/packaged-renderer-check.mjs)
- **知识库子进程缺件，待 Mac 修复。** `KnowledgeHost` 从物理目录启动 `backend/knowledge/process.js`。它加载的 `service.js` 依赖 `eraseLibrary.js`、`indexBatch.js` 和 `indexUpgrade.js`，三者均从上一级加载 `../atomicFile`。Mac 打包器解包整个 `backend/knowledge/`，但在其上一级只单列 `cancellable.js`。请在 Mac 补入 `backend/atomicFile.js`，从最终包的物理入口逐层解析编译后实际使用的相对模块，核对解包标记、磁盘路径及字节。Windows 1.3.0 候选在真实 APPX 升级中已因该缺件无法启动知识库。Mac 结论来自打包配置与共享模块引用，签名包待本机验证。[Mac 解包规则](../macos/scripts/package-app.mjs) · [子进程入口](../shared/electron/backend/knowledge/host.ts) · [索引服务依赖](../shared/electron/backend/knowledge/service.ts)
- **升级后重启知识库。** 在旧包允许表补入正式 1.2.3 ZIP 的固定摘要。在隔离 guest 用该 ZIP 启动旧应用，写入合成原件并建立可检索的索引。升级至最终签名包并完成认领，检索旧文档，导入一份新文档、完成建索引并核对命中正文。正常退出应用后，以同一账户重新启动，读取原件并检索新旧文档，核对引用及已提交索引修订。现有 `package-smoke.mjs` 可以复验 `KnowledgeHost` 的创建和重开。整应用重启须以升级后的签名包验收。[包内知识库检查](../macos/test/scripts/package-smoke.mjs) · [升级数据夹具](../macos/test/scripts/package-upgrade-data.mjs) · [旧版 ZIP 允许表](../macos/test/scripts/package-upgrade-baselines.mjs)
- **深账户目录中的索引。** 知识后端声明可选的 `PrepareKnowledgeDatabase` 回调，主进程把平台提供的实现传给 `KnowledgeHost`。Windows 为长路径下的 LanceDB 写入创建临时 NTFS 联接，表和索引仍在原位置。Mac 沿用账户的原索引目录。用较深的合成账户路径导入 PDF、TXT 与 Markdown，核对首次建索引、全文检索、重启后的修订和归属，以及从 1.2.3 原件重建的结果。[知识后端接口](../shared/electron/backend/knowledge/types.ts) · [Windows 路径适配](../windows/electron/knowledgePath.ts) · [账户装配](../shared/electron/accountProfile.ts)
- **账户分区。** 检查登录窗口使用 `persist:voxcue-login`，同一所有者的主窗口与面试窗口使用 `persist:voxcue-user-<所有者摘要>`，并保持上下文隔离、沙箱开启、Node 集成关闭。在 guest 写入两份可区分的合成账户资料，重启并往返切换。核对旧账号写盘与资源收尾后才加载登录表单，两次登录后均从各自分区读到对应的记录和原件。[账户切换](../shared/electron/main.ts) · [窗口配置](../shared/electron/window.ts) · [账户目录与分区](../shared/electron/accountProfilePaths.ts) · [升级夹具](../macos/test/scripts/package-upgrade-data.mjs)
- **正式包拒绝测试入口。** 检查最终归档未携带项目的测试夹具，并在打包状态下等待 `auth:demo` 的异步调用结果，确认请求被拒绝且未建立演示会话。测试专用开关或数据目录不能让正式包切入演示逻辑。[主进程入口](../shared/electron/main.ts) · [Mac 包安全检查](../macos/test/scripts/package-security-smoke.mjs) · [Windows 包内断言参考](../windows/test/scripts/store-artifact-smoke.mjs)

## 界面与交互逐项验收

**图标按控件位置验收。** 实际面试顶部胶囊的「开始录音／停止录音」连同波形动画保留共享实现。胶囊中设置、截图保护、结束等其他操作以及应用其余界面使用 Mac 端图标。历史播放器目前直接导入静态 `RecordingWaveIcon`，登录页和设置里的 `InterviewPreview` 直接绘制静态 `RecordingWave`。这三处须接入 Mac 图标接口，分别在历史详情、两个预览和真实面试核对。服务商标识仍须与实际服务匹配。[真实面试胶囊](../shared/src/components/FloatingInterview.tsx) · [历史播放器](../shared/src/components/RecordingPlayer.tsx) · [两个预览的共用组件](../shared/src/components/InterviewPreview.tsx)

### 账户、设置与准备页

**登录窗顶部拖动。** Windows 最小登录窗内，演示中已滚出可见区的问题气泡曾让顶部空白处无法拖动。修正仅作用于 Windows 自绘窗控的只读演示。Mac 使用原生红绿灯，本机应在默认及最小尺寸播放演示，核对顶部 72 CSS px 拖动带、红绿灯、登录表单和演示工具栏各自的命中位置。[共享登录样式](../shared/src/styles.css) · [Mac 原生登录验收](../macos/test/scripts/login-actions-native-smoke.mjs)

**滚动条与正文对齐。** Mac 本机待验。使用占宽式滚动条时，分别打开「开始面试」、设置右侧正文和个人信息正文，再切换数据迁移步骤、展开资料分组，打开面试中的模型与设备设置。各正文应从原有右内边距中预留滚动条宽度，溢出时才显示滚动条，标题、表单和页脚保持设计的左右边距。再展开准备页聊天中的长消息、思考过程、来源或技能，在模型菜单中往返「选择模型」与「思考强度」，并在远程手机端切换最近三条转录预览与完整展开。核对聊天阅读区、模型菜单当前页和手机转录区两侧等宽，切换前后内容保持居中。打开主设置和面试浮窗的回答模型列表，核对列表顶边与底部「刷新模型列表」外缘的留白相等、两者之间间隔 6 px，滚动列表时刷新行留在原位。使用系统覆盖式滚动条时，复核这些区域均无额外留白。[桌面滚动区域](../shared/src/styles.css) · [模型菜单](../shared/src/components/reasoningEffortControl.css) · [手机转录](../shared/src/mobile/styles.css)

### 聊天与本地检索

- **聊天与草稿。** 准备聊天每个对话独立持有请求与取消控制器。切到另一对话可并行发送，停止只取消当前对话并保留输入框草稿。IndexedDB 首次写入时将旧整份快照转为逐会话保存，选中才核对附件引用，发送前验证整段上下文最多 20 个附件、单件 20 MiB、合计 32 MiB，再按需读原件。缺损原件只影响引用它的请求。普通编辑 350 ms 合并，离页用已打开的连接写草稿与必要 Blob，重启读取检查点。确认资料提案先记回执再核销。Mac 在 `macos/` 运行 `pnpm test:conversations`、`pnpm test:chat-response`、`pnpm test:chat:progress`、`pnpm test:chat:lifecycle`，用合成会话复核交错生成、停止但保留草稿、坏附件、重载与换号。[会话存储](../shared/src/services/chats.ts) · [会话取消](../shared/src/stores/preparation.ts)
- **附件与流式显示。** HTTP 请求按二进制原始字节及文本字节的七倍估算，整次达到 4 MiB 时分块组装。二进制每 192 KiB 转 Base64，文本每 32 KiB 增量解码、转义，块间允许取消。Copilot 以 Base64 长度或文本六倍估算，只对达到 4 MiB 的 `session.send` 分块填充单份 JSON-RPC 消息缓冲区，再经 SDK 管道写出。SSE 跨块解码 UTF-8 并合并多行 `data:`，能从 `id:`、`retry:` 和注释开头识别流，解析正文时只消费 `data:`。Responses 对齐正文与拒答并用终态补全，公开摘要最多十万字符。资料提案完整解析后约 60 ms 合并预览。Markdown 首段、替换和终态立即显示，连续追加最长等待 250 ms。Mac 用 arm64 SDK 核对取消、消息顺序及背压，并在签名包复核附件读写。[附件编码](../shared/electron/backend/chat/input.ts) · [Copilot 管道](../shared/electron/backend/copilot/attachments.ts) · [SSE](../shared/electron/backend/chat/sse.ts)
- **检索与版本差异。** 1.2.3 已交付 E5/Lance、`qa-linked-v2` 父子问答和 `local-v7-current-source-first` 检索，最多五个证据根。1.3.0 改用 `qa-linked-v3`、`bplus-selected-history-v1`，识别代码围栏外的 Markdown 加粗主问/追问标签。准备聊天通过当前 AI 服务判定该请求是否明确要求使用所选库，校验原文引句和检索词后再读取本地资料。面试可信前文从最多六条收至三条，每条至多 200 个 UTF-16 码元，可携带前文的当前问题由 700 放宽至 6,000 个码元。回溯遇间断或暂停即止，跳过 AI 建议、面试者发言及默认截图题。[面试上下文](../shared/electron/application/interviewContext.ts) · [意图判定](../shared/electron/application/knowledgeIntent.ts)
- **检索实现。** 沿用 384 维 multilingual-e5-small Q8 CPU。向量问题超过 512 token 时保留首尾。按主问取组内最高正文余弦，加本库归一化最高 BM25 的 0.05 倍。独立问题要求第一组的当前问正文余弦达到 0.8811。去空白与标点后不超过 10 字符或有追问线索时可跳过门槛，从可信前文中只选一条，与当前问等权。最近前文有 0.06 加分，明确回指时取消加分。上述生成路径已替换 1.2.3 的项目别名、最多 64 个跨文档重复标题后缀和最多 20,000 行背景向量均值。普通后端查询仍有关键词、向量与混合三种模式，页面提供资料管理。[现行检索](../shared/electron/backend/knowledge/grounding.ts) · [数据库](../shared/electron/backend/knowledge/service.ts)
- **证据与快照。** 最多六个主问，每组优先保留实际命中项，沿父子关系补足至多五个追问。同次回取校验同根、同文档、同库和同修订。知识进程核验命中节选并计算组合正文摘要，应用层按内容摘要与条目 ID 去重。检索和取证共用 15 秒，证据上限 48,000 UTF-8 字节，同时受剩余消息字符预算限制，优先组合正文，放不下时尝试已核实的命中节选。所选证据作为不可信 JSON 附在当前用户消息尾部。可用性失败可降级，身份或完整性错误及主动取消终止。面试同题重试须版本和输入一致才复用完整非空证据。普通索引写入期间可另开读进程查询已提交快照。正文热缓存最多 16 MiB，超限正文验证后当次可复用候选元数据。估算分块缓存超过 64 MiB 后保留词频并逐批读表。最多缓存八个近期问句向量，当前问重编码。[证据核验](../shared/electron/backend/knowledge/evidence.ts) · [预算、重试与失败处理](../shared/electron/application/rag.ts)
- **升级、重建与删除。** 按目录、备份和记录识别无标记/v1/v2 索引，先持久化清理记录再切目录。混合库保留可用 v3 与恢复版本，中断可续办，进度可重放。使用 IndexedDB 原件重建。一次选择最多 20 份，按库将 2–20 份成批暂存后发布一次全文索引，单件单独处理。单件 ≤20 MiB，IPC 在途 ≤40 MiB。若一份失败，先记录其错误，成功回滚后逐件重试其余有效成员。明确取消结束该批。替换、删除使旧写入失效，整库删除先记持久意图并保护其他库，归属不清时暂停。有选库的面试开场按可用提交快照准入，面试期间拒绝新增导入和重建。[清理与恢复](../shared/electron/backend/knowledge/indexUpgrade.ts) · [批量提交](../shared/electron/backend/knowledge/indexBatch.ts) · [整库删除](../shared/electron/backend/knowledge/eraseLibrary.ts)
