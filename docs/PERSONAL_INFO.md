# 个人信息：交互、契约与兼容

更新：2026-10-14。最新用户要求优先于早期回答风格方案。

个人信息沿用右侧面板、共享基础控件、Fluent 图标和当前浅深主题。基本信息只包含姓名与面试语言，没有独立目标岗位。简历、职位描述、自定义指令各为一个内容区，非编辑状态只提供编辑、删除，编辑时底部切换取消、保存。自定义指令只有一份正文，没有条目标题、数量计数或新增条目按钮。技能保留最多十项与可展开的来源。

## 编辑与确认

技能默认只整理3–5项最相关的核心能力，每项约120–220字、1–2个相关来源，不凑满存储上限、不默认写教程/口述稿/追问清单；用户明确要求时才展开。聊天正文只简短说明，完整技能在下方提案出现一次。生成中与完整提案均逐项显示间距和分隔线；全局来源先显示3条，其余可展开，技能自己的已验证来源保持直接可点击。

来源同时从实际完成的流式工具项和最终响应收集，实际打开/查找的网页也属于工具证据。URL 同页片段/明确追踪参数不会导致误拒绝，但不同路径/域名/有效查询仍严格区分；采用工具实际返回的URL/标题。多余未匹配引用移除并警告，任何新增/修改技能没有剩余真实来源时仍禁止保存。失败快照保留已收到的正文与只读预览，明确显示来源校验失败，不能通过确认覆盖原资料。新 errorCode 仅为可选聊天元数据，数据库版本不变，旧失败记录不自动转成可保存提案。

用户可以在准备聊天中提供简历/JD（文字或聊天附件）、指令要求或技能修改，也可在面板点击编辑。聊天中的 AI 会概括简历/JD、将自然语言要求整理成单份提示词。侧栏点击编辑后直接修改现有内容，点击保存立即落盘；取消保留原值。编辑、保存和删除确认均在侧栏内，无编辑弹窗，不发送 AI 请求，也不影响未发送聊天草稿和附件。

准备聊天使用同一次 Responses 的结构化 answer/changes；流式正文只展示 answer，不显示 JSON 协议。AI 可以读取并提出姓名、语言、简历摘要、JD 摘要、自定义指令和技能的修改。主进程拒绝未知字段、非法类型、超长内容、重复技能 ID 和不安全来源。没有直接写个人资料的 AI 工具。

生成changes时通过只读profile-preview实时显示摘要、指令及技能正文，确认按钮禁用；完整生成并通过全部校验后才变成可确认提案。预览不包含未经最终校验的来源链接。停止、失败、重启恢复的未完成内容仍只读，不能确认；迟到事件忽略。普通聊天与预览保存在独立聊天数据库，删除聊天不删除已确认个人资料，未确认提案也不会因恢复聊天而自动保存。

AI 完成且有效的提案只显示待保存内容，不保留前后对比。点击确认更新，或明确输入“确认/确定/同意/确认更新/确认保存/同意更新/同意保存”确认最近完整有效提案后才保存；简短确认和拒绝在本机完成，不另发 AI 请求。本机已保存/拒绝的状态会随后续请求提供，避免模型重复要求文字确认；未处理提案不阻止普通聊天。保留旧版、失败、停止、未完成或过期不会覆盖。每份提案只确认一次。姓名/语言点击保存即确认；删除按钮首次点击变为红色“确认删除”，再次点击才执行，焦点和滚动位置保持。对象及删除范围在悬停/读屏说明中呈现；Esc、失焦或三秒后取消，无顶部提示区或删除弹窗。保存失败保留提案并可重试。内部基线只比较将修改的字段，手动编辑也不能覆盖编辑期间的新值；技能提案额外校验生成时的简历/JD 基线。

确认简历/JD 更新后，两项摘要齐全才主动询问是否联网更新技能。拒绝不会发起搜索，也不撤销已保存摘要；同意才请求生成，生成结果再次等待确认。新增/改写技能必须有本次实际完成的 web_search 事件及返回来源；技能引用必须匹配这些来源，不能以开启搜索开关或模型自称联网作为证据。删除技能无需联网。不能在同一提案中修改摘要并生成技能，需先确认摘要。

缺少简历或JD摘要时，说明已有资料已保存、可以继续普通聊天，并提供具体缺少哪项的可点击补充入口，将引导文本追加到现有草稿并聚焦聊天；不会自动发送。补充草稿只请求整理待确认摘要，不误触发立即联网生成技能。两项齐全且上一回复结束后开放“联网更新技能”；生成中有明确等待说明。

## 知识库与面试

只允许用户在独立选择器选一个知识库或“不使用知识库”。没有官方题库；AI 的 schema/changes 不含选择字段。选择器存储与个人资料分离。已删除的选择明确提示，不回退到全部知识库。

开始面试确认后，主进程深拷贝个人资料与知识库 ID 作为本场配置。浮窗不能通过回答请求替换它们。Local RAG 与 Function Calling 都限定所选库；结果再次按库过滤，工具读取还校验条目所属文档。不选库时跳过检索和知识工具。本场使用已确认摘要、语言、单份指令及技能；技能参考不被当作候选人的真实经历。回答仍只输出可直接口述的专业正文。

## 存储兼容与恢复

- 仍用 copilot-personal-info-v1：background 为简历摘要、jobDescription 为 JD 摘要；新增可选 language、customInstructions 字符串、skills 数组。旧四字段资料仍可读取。
- role 仅兼容旧存储，不再展示、接受 AI 修改或发送到正常准备/面试上下文；不自动擦除真实旧值。
- 试用期若保存过自定义指令数组，读取时在内存按原顺序将标题和内容合并成一份正文；不在加载时改写原始存储。超限/损坏时明确报错并保留原数据。
- 新键 copilot-interview-knowledge-base-v1 仅保存用户选择的库 ID 或 null，缺失默认不使用。旧 copilot-answer-style-v1 只读兼容表达偏好，已确认自定义指令优先；旧风格编辑组件及写入入口已撤除，不清理旧键。
- IndexedDB copilot-local-documents 的版本、stores 和原件没有迁移。旧 personal-resume 原件继续读取；聊天附件和摘要不会写入/替换它。删除摘要不会删除原件、知识库或历史。
- 不做批量迁移/自动保存。恢复前正常退出应用并备份既有 userData；需要恢复某次个人信息时仅恢复该资料键，保留原件库、知识库选择、凭据和历史，不能整库覆盖。没有新增自动历史版本库，提案确认前可保留旧版。

限制：姓名60字、语言80字、两份摘要各10000字、自定义指令16384字；技能最多10项，每项标题80字、正文6000字、来源最多10条。资料总 JSON 长度40000字符。超限拒绝保存，不静默截断。

## 验证范围

pnpm test:profile:ui 使用独立 userData 和合成账户、设备、AI、检索端口，验证完整 UI/IPC/本机存储确认与侧栏直接取消/保存、失败恢复、单份指令、技能更新询问、知识库范围锁定和视觉对齐。单测使用真实 ChatGPTService 的合成 HTTP/SSE 验证网络来源门槛；这些检查不代表真实账户工具资格、摘要语义或技能质量已验收。

全局字体规范：页面/弹窗标题18px、分区标题15px、正文与按钮/输入/选择控件14px、辅助说明12px，字重400/500/600按角色使用。pnpm test:ui:typography 覆盖31个浅深、默认/窄窗口状态，检查实际 computed style 与控件字号，并生成截图。
