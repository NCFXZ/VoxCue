# 面试设置、状态提示与公开摘要检查

## 已落实的行为

- 麦克风测试改为加长、居中的分段音量条。原生 RMS 是线性幅度，原来的 0–1 直接显示使正常语音显得很小；显示现在按 -60 至 -6 dBFS 映射到 0–100%，不改变录音增益。无十秒上限，手动停止、换设备、禁用、切换设置分类或关闭设置时释放采集。
- 删除面试者麦克风 checkbox，在设备下拉框选择“不使用麦克风”；无设备、所选设备失效或测试权限错误在该区域提示。开场重新枚举设备，缺失麦克风仅从本场配置移除，不覆盖保存的偏好；系统音频继续可用。
- 开始确认展示实际系统音频、麦克风、模型和思考强度，并提示去“设置 → 面试设置”修改。删除用户指定的前半句，保留音频本机处理、不保存及必要文字发送说明。没有在打开确认弹窗时开始采集。
- 每场面试自动回答默认开启，浮窗可随时关闭；设置读取及开场解析都不会沿用旧的默认关闭值。顶部工具栏按内容宽度显示，删除固定品牌伸展空位。
- 侧栏生成中显示 Fluent 旋转图标；回复在后台完成后显示主题色未读点，查看后清除。当前页面且窗口获得焦点才算正在查看；离开页面、打开设置或窗口失焦时的完成会标记未读。失败、手动停止不标记为完成。顺带修复删除其他对话会误停后台原对话的问题。

## 摘要的真实边界

截图中的“本次响应未提供可展示的推理摘要”只是空提示，不能视作摘要功能验收。现在生成期间直接显示服务端 Responses 活动状态；收到公开摘要后，才在正文前出现默认收起的“推理摘要”。完成后无摘要就不显示空展开项。主聊天与面试浮窗一致。

已核对官方 [Reasoning 文档](https://developers.openai.com/api/docs/guides/reasoning)：公开摘要需通过 `reasoning.summary` 显式请求，返回 `reasoning.summary[]/summary_text`；原始推理 token 不公开。现有请求确实发送 `summary: "auto"`。补测 GPT-6.1-Sol 的自动/xhigh 请求以及 SSE/完整 JSON；补齐 output_item 与 summary_part 事件接收，终态校准不混入正文，拒绝 raw reasoning/encrypted_content。无效 null 摘要项不再导致正常回答失败。

**真实账户为何没有摘要仍未确认，不能宣称已修复服务端缺失。** 三次隔离诊断均在读取现有登录阶段失败，没有发出网络请求。随后提出的临时复用 Chromium 加密密钥方案被自动审批拒绝，理由是超出摘要诊断授权的凭据材料提取。已删除诊断脚本并停止此路径；没有复制密钥、刷新授权或修改 OAuth。后续真实验证应通过应用正常授权会话开展，不能用模拟摘要证明真实账户成功。
