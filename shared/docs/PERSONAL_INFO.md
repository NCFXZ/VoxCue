# 个人信息：交互、契约与兼容

更新：2026-11-02。最新用户要求优先于早期回答风格方案。

当前共享 0.5.5 实现沿用右侧面板、共享基础控件、平台图标和浅深主题。基本信息只包含姓名与面试语言，没有独立目标岗位。简历、职位描述、自定义指令、面试知识库和技能默认折叠，展开/收起有高度、透明度及箭头动画，减少动态效果时跳过。分隔栏支持拖动宽度、双击恢复380px和方向键/Home，受可用聊天空间限制。自定义指令仍只有一份正文，技能保留最多十项，真实来源元数据仅供后台核验。

## 编辑与确认

提案的技能/长字段详情使用共用Modal的固定覆盖式顶部，与聊天顶部共用材质；正文单独滚动，顶部按钮区按实测滚动条宽度避让，材质横向延伸至弹窗内缘以覆盖右侧占位，轨道从标题下方开始且不被模糊层遮挡。保存此项勾选与关闭按钮间距20px，窄窗口仍沿用自适应换行；勾选只同步选择，不立即保存。

技能支持逐条勾选，按稳定 id 应用所选新增、修改或删除，不用整个提案数组覆盖现有列表。未选的新条目不添加，未选的已有条目保留当前原文与来源；提案中省略的已有条目单列为删除候选，只有勾选才删除。技能总开关支持全选/取消全选与部分选中状态；勾选和实际应用的 id 随聊天保留，保存后逐条标明新增、修改、删除或保留。过期检查只针对所选 id，并继续保护简历/JD 依赖；未选技能的较新修改及并发新增保留。合并后超过十项时明确报错，不截断或自动删除旧项。

提案勾选框统一为16px、6px连续圆角，沿用主题色；勾选/取消和部分状态的勾与横线带透明度、缩放及填色过渡。保留原生 checkbox 的键盘与读屏语义、焦点轮廓，减少动态效果时关闭过渡。

资料提案采用单层紧凑清单：短字段直接显示，长字段只显示两行纯文字预览，点击“查看全文”在共用 Modal 中阅读全文，只有阅读面板内部一处滚动。面板上的“保存此项”勾选与卡片同步，不执行保存。技能分组可展开逐条勾选，仅技能提案默认展开，多字段提案默认收起技能。技能清单按共享240ms曲线过渡高度、透明度和箭头，连续切换从当前进度衔接；内容保留以保持勾选和流式更新，收起时用inert与aria-hidden排除键盘/读屏访问，减少动态效果直接切换。底部集中显示说明与操作，点击“保存所选”一次完成保存；保存后用紧凑状态标记已保存、已新增、已修改、已删除或保持原值，不再堆叠完整正文。

所有待保存字段与技能显示“待新增”“待修改”“待删除”或“保持原内容”标签，避免被误认为已落盘。正在生成的单个字段/技能标题后显示 loading；按实际 JSON 字符串或条目闭合分别结束，不因其他字段仍在生成而继续转动，停止、失败与完成后隐藏。提案总标题没有 loading。预览仅在稳定 id 已完整到达后标记技能操作类型，避免把已有技能误标为新增；进度不持久化，恢复的未完成回复不会残留 loading。

2026-10-20：完整资料提案按姓名、面试语言、简历摘要、职位描述摘要、自定义指令和技能字段逐项勾选，默认全选；确认按钮只保存勾选项，一次确认后结束该提案，其他字段保留当前值。空选择不能保存，勾选状态及实际已保存字段随聊天持久保留；保存后逐项显示紧凑状态，旧记录没有字段范围时仍按原整份保存解释。过期检查只针对所选字段，技能仍额外核对其依赖的简历/JD，避免覆盖较新资料。

按最新用户要求删除下一条消息的文字保存解析。“只保存…”“确认保存”等均进入普通聊天，不执行保存或改变勾选。提示词明确要求引导使用卡片按钮，不以聊天文字宣称保存成功或重复生成提案。已完成部分保存的范围仍进入后续聊天操作状态。

准备聊天移除手动联网开关，默认提供搜索能力，由模型结合任务决定是否搜索；用户要求不联网时遵守。技能可以依据模型已有知识生成，不再强制检索；未搜索时 sources 为空。只限制技能条目的标题和正文不带链接，提案、预览和已保存条目沿用 PlainTextContent 展示；聊天回答（包括技能提案旁的说明）仍使用 Markdown、来源栏和原文复制。旧条目原文与来源元数据不批量改写。

声明了来源的新增/改写技能仍需核对本次实际完成的搜索及返回 URL；匹配采用实际工具 URL/标题，同页片段和允许的追踪参数归一化，不按同域猜测。无来源的知识型提案不标注检索失败。虚构或失配引用从技能 sources 移出，保留在 skillSourceIssues 中供审阅；有效完整提案可由用户选择保存。格式、上限、停止、过期、取消及迟到保护不变，旧记录保持兼容。

用户可以在准备聊天中提供简历/JD（文字或聊天附件）、指令要求或技能修改，也可展开侧栏分区点击编辑。聊天中的 AI 会概括简历/JD、将自然语言要求整理成单份提示词。简历/JD/自定义指令/技能在共用 Modal 弹窗中编辑，保存才落盘，取消保留原值，较新的资料阻止旧编辑覆盖；删除确认仍在原按钮内。手动编辑不发送 AI 请求，不影响未发送聊天草稿和附件。AI 提案和技能更新提示仅在聊天展示，不再同步到侧栏；确认后侧栏显示已保存资料。准备建议由界面统一渲染；手动摘要修改及空聊天/重载后也可操作，同一时刻只展示一个。

2026-11-02：准备引导采用固定标题“接下来想做什么？”、简短副标题、三个快捷选项和小号“使用指南”超链接（`https://voxcue.com.cn/install/`，通过既有受控外链入口打开）。悬停或键盘聚焦按钮时副标题以共享过渡时长淡入淡出为对应说明，离开后恢复；文字共用稳定高度，减少动态效果时直接切换。只在主界面空白新对话页居中显示，聊天记录、资料保存后和已有聊天重载后均不插入引导；不添加阶段卡片或跳过流程。无简历时提供上传、粘贴和补充JD（已有JD则查看资料）；缺JD时提供添加JD、更新简历和开始面试；摘要齐全时提供生成/更新技能、查看资料和开始面试；有技能则显示“更新技能”，没有技能则显示“生成技能”；资料齐全且无待更新时提供开始面试、更新技能和查看资料。

首页建议依据已保存资料生成，上传或待确认提案不算完成；普通聊天和提案旁均不展示。添加资料只追加草稿、保留原附件并聚焦输入，不自动发送或保存；技能仍调用现有单次生成与确认流程；开始面试沿用本地组件检查及现有设备确认对话框。

Modal 内部容器负责长内容滚动，外层裁切圆角且轨道上下内缩，避免滚动条穿过圆角；Escape、关闭与取消均丢弃本次编辑，保存失败保留草稿以便重试。设置沿用独立分类滚动区。

准备聊天使用同一次 Responses 的结构化 answer/changes/skillScope；流式正文只展示 answer，不显示 JSON 协议。AI 可以读取并提出姓名、语言、简历摘要、JD 摘要、自定义指令和技能的修改。主进程拒绝未知字段、非法类型、超长内容、重复技能 ID 和不安全来源。没有直接写个人资料的 AI 工具。

准备聊天主提示词在 shared/src/stores/preparation.ts，ChatGPT/Copilot 共用 backend/chat/profile.ts 的资料协议与意图规则。模型依据当前请求、对话和已保存状态理解操作及“需要／可以／yes”等简短回复，不再依赖中文技能关键词；保存仍只能通过卡片。普通对话跟随用户语言，口述稿默认使用面试语言。附件和网页只是资料，不能授权资料修改。整套技能要求已确认简历/JD；指定主题可以单独生成。内部 skillScope 元数据区分 all/topic，由后台校验完整摘要依赖，不写入个人资料；显式整套入口不能用 topic 绕过校验。

生成changes时通过只读profile-preview实时显示摘要、指令及技能正文，确认按钮禁用；完整生成且格式有效后才变成可确认提案，来源问题保留为可审阅警告。预览不包含未经最终校验的来源链接。停止、失败、重启恢复的未完成内容仍只读，不能确认；迟到事件忽略。普通聊天与预览保存在独立聊天数据库，删除聊天不删除已确认个人资料，未确认提案也不会因恢复聊天而自动保存。

AI 完成且有效的提案只显示待保存内容，不保留前后对比。仅通过逐项勾选并点击“保存所选”保存，不再通过聊天文字执行确认或拒绝。本机已保存/拒绝的状态会随后续请求提供，避免模型重复要求文字确认；未处理提案不阻止普通聊天。保留旧版、失败、停止、未完成或过期不会覆盖。每份提案只确认一次。姓名/语言点击保存即确认；删除按钮首次点击变为红色“确认删除”，再次点击才执行，焦点和滚动位置保持。对象及删除范围在悬停/读屏说明中呈现；Esc、失焦或三秒后取消，无顶部提示区或删除弹窗。保存失败保留提案并可重试。内部基线只比较将修改的字段，手动编辑也不能覆盖编辑期间的新值；技能提案额外校验生成时的简历/JD 基线。

AI新增或修改简历/JD提案且与已保存资料合并后两份摘要都非空时，回复末尾用一句话询问确认保存后是否生成相关面试技能；已有技能则询问更新。待确认提案参与询问条件，JD仅有岗位名称也可询问，不编造缺少的职责或要求。上传/粘贴入口、共享资料规则及响应schema保持一致，“本次不生成技能”不禁止后续询问；用户明确不要询问、缺少摘要、清除、内容未变、普通聊天或本次已处理技能时不追问。不自动生成，用户同意但摘要未保存时先提示确认保存。聊天内不插入提示卡；两项摘要齐全时，新对话首页继续提供生成入口。生成结果仍等待勾选保存。用户同意后交由模型结合本机保存状态生成或更新技能，来源按上述可选检索规则核验；不能在同一提案中修改摘要并生成技能，需先确认摘要。

缺少简历或JD摘要时，首页提供补充入口，只追加草稿并聚焦，不自动发送。两项齐全时首页可生成技能。聊天内不再显示资料保存后的技能提示卡；自然语言请求交给模型判断，条件不足时可询问补充，普通聊天不受阻塞。

整套生成/更新按当前已确认JD重新评估全部技能，可保留、改写、合并、删除无关条目并新增重点；不因旧技能来自简历就保留与当前岗位无关的技术细节，也不虚构JD要求来迁就旧技能。用户指定保留的条目仍保留；同一条目沿用稳定id，不同主题使用新id。仅针对指定主题新增/改写时保留其他已有条目。所有删除仍以待删除项展示，只有勾选并点击保存后生效；单独更新JD不直接修改技能。

## 知识库与面试

只允许用户在独立选择器选一个知识库或“不使用知识库”。没有官方题库；AI 的 schema/changes 不含选择字段。选择器存储与个人资料分离。已删除的选择明确提示，不回退到全部知识库。

准备聊天（包括生成/更新技能）默认不使用所选知识库。有选择时，application/knowledgeIntent 使用当前服务和模型、该模型支持的最低思考强度判断当前请求是否明确要求使用；只传最近对话文字，不传个人资料/附件或开放工具。结合上下文理解各语言的短确认，生成技能、允许联网、选择库本身不算授权。仅有效肯定决定且引用了当前用户原话时才检索，查询限定6000字符；不明确、格式无效或过长文档输入不触发读取，服务错误/取消沿原错误语义终止。无库则直接回答，模型提示先选择再使用。默认回答不沿用历史KB转述；明确使用后的内容仍是待核实参考，不默认当成事实。普通面试继续使用开场确认的库。

开始面试确认后，主进程深拷贝个人资料与知识库 ID 作为本场配置。浮窗不能通过回答请求替换它们。Local RAG 与 Function Calling 都限定所选库；结果再次按库过滤，工具读取还校验条目所属文档。不选库时跳过检索和知识工具。本场使用已确认摘要、语言、单份指令及技能；技能参考不被当作候选人的真实经历。回答仍只输出可直接口述的专业正文。

## 存储兼容与恢复

- 仍用 copilot-personal-info-v1：background 为简历摘要、jobDescription 为 JD 摘要；新增可选 language、customInstructions 字符串、skills 数组。旧四字段资料仍可读取。
- role 仅兼容旧存储，不再展示、接受 AI 修改或发送到正常准备/面试上下文；不自动擦除真实旧值。
- 试用期若保存过自定义指令数组，读取时在内存按原顺序将标题和内容合并成一份正文；不在加载时改写原始存储。超限/损坏时明确报错并保留原数据。
- 新键 copilot-interview-knowledge-base-v1 仅保存用户选择的库 ID 或 null，缺失默认不使用。当前共享第6组清理已弃用的回答风格：不再读取 copilot-answer-style-v1、维护风格状态或追加风格提示词，旧键保留原样；已确认自定义指令仅在面试阶段生效，损坏的旧风格数据不影响资料读取。
- IndexedDB copilot-local-documents 的版本、stores 和原件没有迁移。旧 personal-resume 原件继续读取；聊天附件和摘要不会写入/替换它。删除摘要不会删除原件、知识库或历史。
- 不做批量迁移/自动保存。恢复前正常退出应用并备份既有 userData；需要恢复某次个人信息时仅恢复该资料键，保留原件库、知识库选择、凭据和历史，不能整库覆盖。没有新增自动历史版本库，提案确认前可保留旧版。

限制：姓名60字、语言80字、两份摘要各10000字、自定义指令16384字；技能最多10项，每项标题80字、正文6000字、来源最多10条。资料总 JSON 长度40000字符。超限拒绝保存，不静默截断。
