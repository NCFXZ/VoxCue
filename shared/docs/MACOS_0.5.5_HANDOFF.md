### 必须采用的最终规则

实现过程中用户数次调整方案，下列最终规则覆盖旧进度记录和较早截图：

1. **仅在提案卡片勾选并点击“保存所选”时保存。** 已删除“确认更新”“只保存简历摘要”“只更新姓名”等聊天文字的本地保存解析，也不再解析文字拒绝。正常聊天继续发送给模型；模型说“已确认”不能造成真实落盘。
2. 点击“保存所选”即执行一次保存，**没有第二次确认**；查看全文弹窗内的“保存此项”只是勾选项，不是保存按钮。
3. 普通字段逐项勾选；技能必须细到每一条。**未选字段及未选已有技能保持当前值**，不能整组替换或误删。
4. **提案总标题不加 loading。** 只有实际仍在生成的字段、技能组和单条技能显示；已完成项及时隐藏，不能等待整轮回答结束。
5. 尚未保存的操作使用“待新增 / 待修改 / 待删除”，所有普通字段也要显示。相同内容显示“保持原内容”；保存后另显示实际应用状态。
6. 来源校验问题保留正文和具体原因，供用户审阅后直接保存完整有效提案。语法、格式、完整性、拒绝、停止、过期、存储失败等保护继续有效。

实现入口：`shared/src/stores/preparation.ts`、`shared/src/components/ProfileProposal.tsx`、`shared/electron/contracts/profile.ts`。

普通字段为姓名 `name`、面试语言 `language`、简历摘要 `background`、职位描述摘要 `jobDescription`、自定义指令 `instructions`；技能为 `skills`。面试知识库选择不是新增的提案字段，不应被这里的保存覆盖。

| 编号 | Mac 操作                                                                                                                     | 通过标准                                                                                       |

| P02  | 只勾选“简历摘要”，点击一次“保存所选”                                                                                         | 简历实际落盘，其他所有当前字段不变；没有第二次确认或再次生成；侧栏与重新启动后值一致           |
| P03  | 取消全部勾选，再尝试保存                                                                                                     | 提示选择内容，按钮禁用；即使直接调用保存入口也拒绝空选择                                       |
| P04  | 点击“保留原资料”                                                                                                             | 所有原值保持，提案进入已处理状态；不能再次应用旧卡片                                           |
| P05  | 提案生成后在侧栏修改一个未选字段，再保存其他所选字段                                                                         | 未选字段的新值保留；不因无关字段变化阻塞保存                                                   |
| P06  | 修改将要保存的同一字段，再保存旧提案                                                                                         | 明确提示资料已变化，需要重新生成；不能覆盖较新的值                                             |
| P07  | 注入本地存储容量/写入失败，再恢复后重试                                                                                      | 不误报已保存，不丢原资料；保留提案、选择和错误，恢复后可重试                                   |
| P08  | 重复点击已应用卡片，或尝试保存失败/停止/不完整/已拒绝的提案                                                                  | 不重复应用，不回退到其他旧提案；未完成内容仍可查看                                             |
| P09  | 发“确认更新”“只保存简历摘要”“只更新姓名”“暂不更新”等文字                                                                     | 进入正常聊天，不由本机解析后保存/拒绝/重新启用旧卡片；真实资料保持到用户点击卡片               |

保存入口根据消息里的已验证提案取值，不能用调用者额外传入的数据绕过选择。保存顺序是先写个人资料，再标记消息已应用；过期比较只检查所选字段。没有新增服务器资料写入。

## 3. 每条技能独立选择、删除与并发保护

新增 `skillProposalEntries` 将提案与基线按稳定 `id` 比较，列出新增、修改、保持和删除候选。提案省略已有技能时，该技能成为可勾选删除项，**不是立即删除**。`mergeSelectedSkills` 以保存当时的当前技能集为底，只应用所选 id；未选已有技能的正文、标题、来源与顺序保持，选中新技能按提案顺序追加。

使用合成基线 A、B、C：提案修改 A、保留 B、省略 C、添加 D，可以覆盖下列全部分支。

| 编号 | Mac 操作                                            | 通过标准                                                         |
| ---- | --------------------------------------------------- | ---------------------------------------------------------------- |
| S01  | 展开技能，只选 A 和 D 保存                          | 只修改 A、添加 D；B 和未选删除候选 C 保持原文、来源和顺序        |
| S02  | 只选 C 的“待删除”行保存                             | 只删除 C，A/B 仍是保存前当前值，D 不加入；删除状态在卡片明确显示 |
| S03  | 切换技能组父级勾选，再只取消一条                    | 父级依次正确表现全选、清空和部分选中横线；各技能与父级状态同步   |
| S04  | 取消技能组，仅保存普通字段                          | 技能集完全不变，不意外清空、不回退已有技能                       |
| S05  | 提案技能数组为空，检查旧技能删除候选并部分选择      | 只删除所选候选；未选旧技能继续保留                               |
| S06  | 提案生成后新增/编辑一个未选已有技能，再保存其他技能 | 并发新增及未选修改保留，不全量覆盖当前技能集                     |
| S07  | 改动所选技能；或另一处已创建同 id 的所选新增技能    | 判定旧提案过期，不覆盖新内容                                     |
| S08  | 改动简历或职位描述摘要，再保存旧技能提案            | 即使技能本身未变也阻止过期依赖覆盖，要求重新生成                 |
| S09  | 合并所选新增项后超过 10 条                          | 明确提示减少新增或选择删除，不截断、隐式删除或保存半份资料       |
| S10  | 选择部分技能，切换聊天/重载，再保存并再次重载       | 未保存选择和实际应用的 id 均可恢复；未选内容不误标已新增/已修改  |

所选候选 id 只能来自基线与本次提案的并集，未知 id 不接受。后续聊天上下文同时传递实际保存的字段及技能 id，不能将未选技能描述成已保存。

## 4. 来源校验失败改为逐条审阅

实现入口：`shared/electron/backend/chat/proposal.ts` 的 `verifySkillProposal`，共享事件/返回协议及 `ProfileProposal` 阅读面板。

| 原因码                   | 界面需要说明的具体问题       |
| ------------------------ | ---------------------------- |
| `search_disabled`        | 本次未启用联网检索           |
| `search_incomplete`      | 本次联网检索没有完成         |
| `search_sources_missing` | 检索没有返回可核对的来源     |
| `skill_sources_missing`  | 此条技能未给出来源引用       |
| `source_unmatched`       | 引用不能对应本次真实检索来源 |

只有匹配本次真实工具结果的来源元数据进入技能 `sources`；未匹配的标题/链接保留在消息 `skillSourceIssues` 供查看，不能冒充已核验来源。完全未变化的已有技能不重新要求来源；纯删除不要求重新联网。

| 编号 | Mac 操作                                                                | 通过标准                                                                           |
| ---- | ----------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| R01  | 分别模拟上述五类问题并完成合法技能提案                                  | 正文保留，不再将整份提案判为来源错误而卡死；具体问题关联正确技能                   |
| R02  | 一条来源正常、一条部分匹配、一条全部失配                                | 逐条准确显示“来源待核验”；已匹配来源采用真实工具元数据，失配链接在详情保留         |
| R03  | 打开有问题技能详情，再勾选并保存                                        | 可审阅后一次点击保存，问题警告不导致二次确认；重新打开聊天仍能查看原问题           |
| R04  | 只勾选没有问题的技能                                                    | 未选技能不因来源问题影响此次保存；未选技能原内容保持                               |
| R05  | 构造超长/非法 schema、拒绝输出、被停止或未闭合 JSON                     | 仍拒绝保存，不能用“来源改为警告”绕过格式和完成性保护                               |
| R06  | 缺少已确认简历/JD时发起整套技能；或同份提案同时改摘要并生成依赖它的技能 | 保留已有前置限制。指定主题技能的既有例外保持；不能据此宣称所有离线技能任务都可生成 |

本轮改变的是**完整有效提案的来源诊断处理**，没有撤掉任务入口、URL 格式、个人事实、长度、最多 10 条技能或依赖摘要的边界。检索失败也不能在回答中虚构“已完成联网检索”。

## 6. 流式生成进度：每项完成即隐藏 loading

后端 `ProfileAnswerStream.preview()` 解析不完整 JSON，同时记录已闭合的路径；新增 `ProfileGeneration { fields, skillIndexes }`。`profile-preview` 事件除了预览文字还传进度，去重同时比较文字与进度，避免“内容没变，只补上引号/括号”时漏发完成状态。字段顺序不作为完成判断依据，也不依赖 UI 定时猜测。

| 编号 | 依次输入的合成流/操作                                | 通过标准                                                                         |
| ---- | ---------------------------------------------------- | -------------------------------------------------------------------------------- |
| L01  | 先输出姓名字符串，再关闭它，随后继续语言/摘要        | 姓名生成时显示环；字符串闭合就隐藏，此时后续字段仍能继续生成；总标题始终没有环   |
| L02  | 依次生成语言、简历、职位描述、自定义指令             | 每一实际出现且未完成字段各有环；已闭合字段不再转，不能只给摘要或技能加环         |
| L03  | 技能 1 完整对象闭合，技能 2 继续输出                 | 技能 1 没有环，技能 2 有环；技能数组未闭合时组标题仍显示生成状态                 |
| L04  | 技能数组闭合，但整轮回答暂未结束                     | 所有字段和技能完成后不再有环；不能统一使用 message streaming 状态让完成项一直转  |
| L05  | 闭合引号/括号单独一个分片到达，正文未改变            | UI 仍立即收到完成进度，隐藏对应环                                                |
| L06  | 乱序字段、转义引号/Unicode、空技能数组和尾部空白分片 | 正确识别真实闭合；不凭内容长度、逗号或空白创建虚假技能/完成状态                  |
| L07  | 生成过程中停止、失败或拒绝                           | 已收到内容保留供看，所有环隐藏，保存禁用；不会将不完整预览转成有效提案           |
| L08  | 生成中切换聊天，再完成/停止；重启后恢复聊天          | 事件仍归属原会话；恢复的中断消息为停止状态，没有永久 loading                     |
| L09  | 系统减少动态效果开/关                                | 环形状态可见，减少动态效果时静止，普通状态约 1 秒一圈；14px 主题色图标不撑高标题 |

流式技能预览仅接受完整、符合 `/^[\w-]{1,64}$/` 的稳定 id；部分/非法 id 不向 UI 冒充稳定 id。单条技能完成以对象闭合为准，普通字段以字符串闭合为准；最后仍需整个正式响应通过完整 JSON/schema 校验，预览从不授权保存。生成进度是瞬时状态，不写入聊天快照。

## 7. 技能更新提示：点击任一操作立即消失
