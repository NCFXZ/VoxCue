# VoxCue Windows 1.3.3 → 1.3.5 交接

Windows 的公开基线为 Git 标签 `v1.3.3`，对应提交 `8a52374`。在 Windows 本机从 `main` 接续 1.3.5，共享改动已集中在 `shared/`。Windows 安装包、商店包和原生验收交由本机完成。[Windows 1.3.3 正式基线](https://github.com/NCFXZ/VoxCue/releases/tag/v1.3.3)

[1.3.5 中英文用户更新说明](1.3.5_UPDATE.md)

## 共享界面逐项更新

1. **侧栏收展**。侧栏宽度、导航、聊天记录标题与底部邮箱使用同一套非线性缓动。折叠时圆点直接滑向收起后的位置，选中蓝条逐帧跟随聊天行。展开时文字按既定顺序淡入。挂载后通过当前窗口读取「减少动态效果」，兼容三个侧栏额度静态渲染用例。
2. **聊天记录增删和更新**。新增条目渐显，删除后相邻条目补位。更新时保持条目身份和选中状态，支持减少动态效果。
3. **知识库卡片**。新增和删除时，原卡片从行边缘轻滑淡出，随其他卡片补位从目标行边缘滑入。卡片标题、图标、状态与底部入口通过同一张卡片参与动画。
4. **知识库文档与详情**。文档新增、替换和删除有进出与补位动画。详情窗口随内容非线性伸缩，在窗口允许的高度上限内调整，达到上限后文档区滚动。关闭详情时原地淡出，整库删除后的卡片补位与淡出顺序衔接。
5. **待发送附件**。多行附件沿行边缘淡入淡出。首项和末项移除、换行以及最后一行收起与输入框高度协调，底边与发送工具栏固定。
6. **两个输入框的高度**。面试准备和实时面试在自动换行、删字、清空、达到上限时连续变化。达到编辑区上限后在框内滚动。
7. **面试确认按钮**。「确认显示面试窗口」与「确认结束面试」按图标和当前语言文案计算展开宽度，左右内边距一致。
8. **麦克风预检与录音设置**。「开始面试」按当场音源集中显示预检与可用操作，面试设置中缩短设备选择到自动录音的间距。Windows 使用本机音频和隐私设置适配，按 Windows 设备状态复验。
9. **图标与波形**。共享登录与退出登录图标为配套的方框箭头，更新完成通知使用无外框列表图标。录音预览及「选择录音」共用 18 × 18 px 波形，双路音量显示为五条圆端波形。Windows 本机核对「个人信息」图标为 16 × 16 px。
10. **紧凑注册与追随滚动**。紧凑注册和重置密码界面给验证提示预留高度。长对话追随浏览器的实际滚动底部，复验 125% 等分数缩放下的回到底部行为。

## 知识库索引与删除逐项更新

1. **按库隔离**。每个库在 `libraries/` 下使用独立的索引目录与写进程。删除一个库时终止并清理该库的工作，其他库继续建索引和检索。
2. **从 1.3.3 升级**。持久化旧共享索引的清理记录，删除旧生成索引，使用保留的原始文档自动重建各库。通过现有知识库进度显示重建。新布局里已存在并有效的索引直接继续使用。
3. **后台删除**。确认删除知识库或文档后先持久化任务，界面显示「正在删除…」。用户可关闭详情或继续使用其他库。退出时未完成的任务随下次启动续做，失败可以重试。
4. **同库竞争处理**。删除请求和索引任务按归属处理，取消后的旧进程写入不能恢复待删内容。待删除文档和库拦截冲突写入。文档删除通过确认时的修订校验保护同名替换后的文件。
5. **空库快速删除**。本次运行中刚创建且从未导入文件的空库可直接完成本地删除。旧资料库按其持久所有权处理。
6. **安全与原件**。索引迁移和删除校验目录类型、库归属和生成索引文件名，清理可重试。升级验收应核对原始文件字节、可检索内容、引用、资料历史及重启后的行为。
7. **账号迁移与清理**。迁入资料前读取本地待删记录，保护文档和知识库归属。清理未激活的旧账号时按其当前索引格式处理选定资料，避免触发整库重建。
8. **RAG 复验范围**。本轮只用新建合成资料验证导入、建索引、关键词和向量检索、引用、替换、删除及重建。沿用现有模型、阈值、重排和其他检索参数。后台删除恢复已加入共享功能套件。

## 这轮测试发现并修复的问题

1. **音频设备定位高亮**。收紧录音设置后，高亮下缘贴着设备选择按钮。只延伸定位高亮的背景范围，正常页面布局仍可按设备与录音间距验收。
2. **英文结束确认回归**。英文测试仍等待旧版固定宽度，导致新版本按内容伸缩时超时。现在等待实际确认按钮与动画完成，再验证英文文案和两侧留白。
3. **知识库详情的头部溢出**。标题栏背景在滚动条预留区域用阴影补齐底色，修复字体验收发现的横向溢出。关闭按钮保持 24 px 内边距，滚动控件正常接收输入。
4. **管理页面侧栏对齐**。测试按折叠宽度变量和展开几何尺寸等待动画结束，再执行控件与滚动区域对齐断言。折叠分割线的宽高使用数值比较，容纳 175% 缩放下 Chromium 的亚像素取整。Windows 应沿用共享测试。
5. **Mac 归档生命周期夹具**。使用项目的断网合成账号入口启动，验证重载、关闭和登出后的归档临时文件回收，继续检查迟到调用被拒绝。Windows 若增加同等覆盖，沿用本机合成入口。
6. **Mac 打包与发布回归**。静态验包与打包共用编号副本判定，核对正式资源字节。重新生成当前版本本地启动入口验证单实例。带真实归档的差分测试从文件名读取版本。
7. **Mac 1.3.3 升级夹具**。加入已发布 1.3.3 的固定 ZIP 摘要，按其实际资料结构建立合成账户状态，核对共享索引重新生成和后续重启可检索。Windows 需要使用自己的 1.3.3 已发原包和数据路径。
8. **Mac 来宾权限验收**。屏幕捕获使用未修改的正式应用，麦克风使用隔离测试宿主调用正式包内的签名音频助手，覆盖真实系统弹窗、拒绝、重新授权和重启。应用预检界面另用合成账号覆盖。Windows 本机应使用自己的隐私权限流程复验。

## Windows 本机复验与发布

1. 执行 `node shared/scripts/sync-platform-manifests.mjs` 生成 Windows 1.3.5 配置并核对工作区与架构。依赖复用 Windows 锁定安装，版本来源为 `shared/package.json`。
2. 执行共享源码测试、对抗性和功能套件，运行 Windows 本机 UI 矩阵。重点查看浅深主题、中英文与五档缩放下的侧栏标记、跨行补位、附件区伸缩、知识库详情和长文案。
3. 使用两套合成知识库验证并行索引和删除互不阻塞。覆盖空库、索引中删除文件与整库、后台删除时退出并重开、迁移中断恢复、同名替换、索引引用与原件校验。
4. 使用已发布的 Windows 1.3.3 EXE 和 Store 原包分别建立升级基线。用本机 Windows Sandbox 或自有虚拟机核对安装、升级、真实麦克风与截图权限、正常退出和包内运行时。Mac 验收只证明 Mac 包与共享场景在相应环境的行为。
5. 验证 Windows CPU／CUDA、固定公开模型和音频夹具、恢复与稳定性。按本机规则生成 EXE、blockmap、签名清单及 Store 包。
6. Windows 资产验包后追加到 GitHub `NCFXZ/VoxCue` 的 `v1.3.5`，并镜像至 CNB 的同版本发行。平台选版须能跳过只有 Mac 资产的 1.3.5。追加后保留 Mac 的 DMG、ZIP、增量计划和签名清单，核对 Windows 新旧 blockmap、匿名下载、摘要和全量回退，再合并 CNB Windows 公开索引。Microsoft Store 单独提交并记录认证状态。
