## 2. 最终产品行为

### 2.1 渐隐与阅读字号

- 面试回答滚动区底部36px透明渐隐，底部留白同为36px；返回最新后最后一行完整可读，适配透明/毛玻璃背景。
- 返回最新按钮悬浮在输入框上方；生成时为圆形依次跳动的三点，结束后恢复圆箭头，遵循减少动态效果偏好。只定位最新，不重新发送。
- 12–24px面试阅读字号仅作用于转写、问题、回答气泡及Markdown正文/标题；气泡内首次“正在生成回答…”占位同样跟随阅读字号。
- 实际与设置预览输入框/占位固定14px；思考/活动文字固定14px，服务名、时间、工具栏、状态和警告按既有UI字号显示。

### 2.2 自动重试与取消

- 首次请求失败后最多再试3次，共最多4次请求；等待依次为0.5、1、2秒。空回答也进入失败重试。
- 同一回答复用最初的问题、个人资料/上下文、模型、思考强度和原截图快照；中途改设置只影响后续问题。重试不重新捕获屏幕。
- 主进程通过类型化 `interview-retry` 事件发送次数；Renderer服务名称旁用固定12px胶囊显示“正在重试 n/3”。初次生成占位与重试次数分开显示。
- 重试期间保留已收到的部分正文；新尝试第一次正文到达时替换旧正文，后续追加，成功再用完整返回值校准，不能拼接多次答案。
- 只有成功且未取消的完整结果进入本场AI建议上下文，并消费对应截图。全部失败或停止时原截图仍可手动重试。
- 点击停止取消等待计时和活动请求，不再追加重试；结束面试、关闭/销毁浮窗同样取消。旧尝试、已取消请求的迟到输出不能写入。
- 停止后下一题正常提交；明确停止不显示失败警告，也不会自动恢复。

### 2.3 错误与圆角

- 每条失败回答下方有独立紧凑警告卡；最新和历史警告都随对应回答滚动，输入框上方没有固定警告。
- 标题/次数和右侧重试按钮同排，错误原因位于下一行；长错误仅占一行高度并可内部滚动。普通与最小窗口使用相同布局。
- 有正文时保留正文，未收到正文时不把错误塞进大字号回答气泡；错误原因固定14px，标题15px，次数/按钮12px。
- 当前最新失败为无障碍 `alert`，历史失败为 `note`；服务旁另显示失败状态，同一生成错误不重复出现在浮窗底部。音源、截图、保存等其他错误保持原处理。
- 警告卡和回答气泡共用 `--radius-interview-answer: 32px` 与 `superellipse(2)`；重试按钮沿用14px连续角，状态标签为圆弧胶囊，警示图标/返回按钮/三点为圆形。
- Chromium实际以原生近似路径绘制连续角；本轮检查目标样式与一致性，不宣称渲染曲线严格满足数学G3。

### 2.4 移除来源未核验提示

移除技能详情整块“来源未核验”说明、来源标题/URL、左侧竖线，以及技能总行、逐项行、保存区的“来源待核验”标签。旧消息重载后也不再显示。正文、逐项勾选、保存、后台来源匹配和元数据保持；没有通过UI隐藏取消后台校验，也没有修改提示词。

## 3. 代码与协议

`ipc/interview.ts` 仅在最初快照内增加有界重试。尝试结束后关闭事件接收；等待与生成共用AbortSignal并清理监听/计时器。请求装配从内联移到局部变量，提示词内容相同。

`contracts/chat.ts` 增加 `interview-retry` 事件；`services/contracts.ts` 的Answer增加可选 `retry: { attempt, limit }`。`services/speech.ts` 接收重试事件并在首次新正文时通知替换；store只在未取消时更新，成功清除重试状态。既有IPC频道、preload接口和历史键不迁移。

`InterviewAnswerStatus.tsx` 负责服务名旁状态和紧凑失败卡。`FloatingInterview.tsx` 将警告直接放入所属回答article。清理失效的输入/警告包裹层和样式，返回按钮直接依附已有输入表单定位，原提交/停止逻辑保持。

## 4. 模型复用与测试资料清理

用户最新约定：每次测试只读校验正式版已下载模型，再复制到自有系统临时目录；结束删除全部测试副本/资料，不保留测试缓存，正式原模型保留。

`VOXCUE_TEST_COMPONENT_CACHE` 必须由执行者明确指定；没有自动扫描真实用户目录。`verify-model-cache.mjs` 检查组件标记、完整文件列表、大小/SHA256及链接；`model-fixtures.mjs` 复制后再次校验。不能直接把正式目录传给隔离Electron，既有临时根/所有者保护继续生效，不能为复用放宽。

不得在正式模型根调用组件 `status/download/remove`，因为status也可能清理过期暂存。测试中的删除、取消、损坏和句柄检查只作用于隔离副本。账户、个人资料、凭据和真实历史不在本次模型读取授权内；没有硬件采集。

Windows额外 `qwen-installed-smoke.mjs` 使用同一显式模型源及开发机 `VOXCUE_PYTHON`，复制Qwen至临时根，执行CPU/CUDA、原生/Worker和后台切换；结束重新核对正式源哈希并清理副本/CUDA缓存。此为Windows入口，不能在Mac套用；Mac继续自己的CPU/Metal原生回归。

## 5. Mac 本机执行顺序

1. 先保护Mac本机未提交工作，再安全更新本交接提交；不要整库reset/clean，不覆盖固定凭据助手、签名身份和用户模型。
2. 在Mac仓库根执行 `pnpm sync:workspace`。确认仅本平台生成配置及根入口发生预期变化，依赖和锁中既有版本保持。
3. 执行 `pnpm check:workspace`、`pnpm check:architecture`、`pnpm typecheck`、`pnpm test`、`pnpm build`。Windows专属目录只读。
4. 在 `macos/` 目录执行下列定向共享检查；需复用已有模型时显式设置本机授权缓存路径，所有模型副本在临时根清理。

```sh
export VOXCUE_TEST_COMPONENT_CACHE='<本机明确授权的 component-cache 绝对路径>'
node ../shared/test/scripts/functional-suite.mjs interview-typography interview-retry interview-screenshot chat-progress profile-selection ui-alignment ui-refinement typography
```

5. 逐项执行第6节。语音/窗口/权限、固定凭据助手及真实签名包继续使用Mac既有隔离入口；不得用Windows通过代替这些结果。本轮不授权新的Mac打包/发行或真实安装替换。

Mac生成配置待办：`macos/package.json`、`tsconfig.json`、`tsconfig.electron.json`、`tsconfig.contracts.json`、`vite.config.mjs`、`pnpm-workspace.yaml`；以本机生成器输出为准，不复制Windows配置。
