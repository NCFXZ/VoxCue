# 后台任务背压与恢复

本次按最小修改原则审查客户端各功能入口。保护留在各模块自身，不引入全局调度器，正常用户操作流程保持；索引始终单任务，仅调整后台排队与恢复。服务端、平台专属实现、模型、索引格式及依赖保持。

| 功能 | 已有保护及本次处理 |
| --- | --- |
| 准备聊天、联网搜索、技能提案 | Renderer 的发送状态和主进程 `activeChat` 限制重复发送；请求 ID、取消及迟到事件隔离保持。聊天持久化已有单写入者与一份最新待写快照，继续使用。 |
| 聊天附件、文件夹导入 | 文件数量、单文件大小、目录深度与遍历数量限制保持；不另设会改变正常导入数量的队列。 |
| 面试回答、自动提问、停止和重试 | 单个活动回答、按问题聚合的自动提交、取消旧请求、有限重试与场次隔离保持。 |
| 语音、设备切换、尾段保存 | 既有串行设备协调、PCM 帧大小与音频积压上限、持续间断失败保护保持；不改采样、VAD、识别参数或尾段冲刷。 |
| 截图、归档、查看与导出 | 单次捕获、五张暂存上限、原图大小及 ID 校验保持；不改变用户明确发送及系统对话框保存流程。 |
| 记录、自动标题、关闭保存 | 标题按记录去重、最多二十项、串行生成及单项超时保持；手动标题与删除记录的迟到结果保护保持。关闭仍等待实际保存结果。 |
| 邮箱主账号、AI 授权与额度 | 已有登录互斥、凭据刷新合并、轮换保护、额度操作互斥及心跳保持；不新增认证缓存或生产请求。 |
| 本地组件、应用更新 | 已有单个下载任务、重复请求复用、流式写入、超时、校验与取消保持；不改变面试禁装、保存确认或更新身份。 |
| 云同步 | 继续使用单工作者、单块传输、个人信息优先及 Retry-After。首次恢复先校验文件头以发现知识库归属，再完整恢复一库后处理下一库；首块缓存最多 4 MiB。父级状态包含云端待恢复文件，恢复写入不伪报本地编辑。未完成首次下载的暂停项有独立标记，恢复时继续下载，避免误删云端副本。 |
| 知识库索引 | 新增单个执行者及按文档去重的元数据队列；云端每收到一个完整文件立即入队，不等待尚未下载的同库文件。多库都有任务时，优先处理完当前库已收到的文件，再进入下一库。执行前读取最新原件，并使用其实际本地版本标记任务；删除后跳过，替换后使用新内容。排队时不预读原件字节。状态读取合并，失败的同一原件冷却一分钟，防止重复开库形成重试风暴；正常的后续文件继续执行。 |
| 启动、开库与批量恢复刷新 | 主窗口连接索引状态；模型就绪后检查全部原件，打开知识库时检查该库。检查只补齐缺失或停用的索引，已就绪和处理中项跳过。重复检查合并，每库已存在的缺失项整组入队，单任务逐份执行；云端文件连续落盘时最多一个知识库列表刷新及一次合并重查。 |

实现集中在 `src/services/cloudSync.ts`、`src/services/cloudData.ts`、`src/stores/cloudSync.ts`、`src/stores/knowledgeIndex.ts` 与 `src/stores/knowledge.ts`。`App.tsx` 只承接主窗口生命周期和现有同步通知；索引模块通过原件存储与已有公开知识库 IPC 工作，不依赖云同步、聊天或面试 Store。

回归入口：`cloud-sync.test.ts`、`cloud-data.test.ts`、`cloud-sync-store.test.ts`、`knowledge-index-store.test.ts`、`knowledge-reconcile.test.ts`，以及 `pnpm test:knowledge` 中的隔离云恢复、开库补索引及启动补索引场景。聊天、面试、语音、截图、记录、组件、更新与认证继续由各自单测及桌面入口覆盖。测试只用合成账户/原件与临时目录，执行结果仅终端显示；Mac 共用逻辑回归不替代 Windows 本机原生、DPI 或真实账户/硬件验收。
