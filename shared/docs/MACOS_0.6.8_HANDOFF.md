# Mac 0.6.7 → 0.6.8 逐项更新与验收

## 基线、范围和执行顺序

- RAG 沿用 0.6.7 既有实现；只验证面试中可正常调用及原有调用链、错误和取消收尾，不做语义质量优化，不调整算法、权重、阈值、模型、专项脚本或架构文档。
- 本轮在 Windows 完成；`macos/` 全树只读。共享功能和契约改动随源码交付，Mac 必须在本机逐条复核，不以 Windows 合成窗口、原生或安装包结果代验。
- 对比基线为 Mac 0.6.7 正式包源码 `0178df3802e3018b67655f2fbd59593f9d29d546`；到本轮起点 `1882bf6` 的后续提交仅文档，以下逐项覆盖本轮产品、契约、窗口、测试调度与清理改动。
- 版本唯一来源为 `shared/package.json = 0.6.8`。源码和 Windows 发行输入见 [Windows 0.6.8 发行索引](WINDOWS_0.6.8_RELEASE.md)。本轮不升级依赖、SDK 或模型，不部署官网、独立服务端，不修改身份、凭据和历史数据兼容。
- Mac 拉取前先检查 status/diff，保留本机后续工作；运行 `node shared/scripts/sync-platform-manifests.mjs`，只生成本机与根清单。在 `macos/` 同步自己的依赖锁，不复制 Windows 锁，不修改 Windows 树。Windows 报告的 Mac 清单漂移只读保留，交由本机生成。
- 按下表逐条输出“通过 / 修复后通过 / 待验 / 不适用”、依据、失败原因和复测入口到终端或对话；不把测试报告、截图或成绩写回仓库。仅使用 owner 临时合成账户、资料和固定公开模型/音频。
- 原生/GUI 只在当前 UID 已登录且解锁的控制台串行执行；不修改辅助功能或锁屏权限。保留 Mac 原有自然工具栏高度、原生材质、权限、签名、凭据和更新装配。

## Mac 测试流程优化边界

本次允许优化测试编排、合并重复准备、复用现有校验后的公开模型与音频缓存；优化前后须逐项核对功能清单、平台矩阵、输入、断言、超时、取消及清理，不能用减少测试覆盖换取速度。

- 仅 `cloud-protocol`、`server-connection`、`telemetry-v2-http` 三组已审计的独立 Node/loopback 检查可并发，默认最多两个，显式上限三个；临时数据库、随机端口与 owner 目录各自独立。全部结束后再进入独占组。Mac 原生界面、权限/凭据专项、RAG/语音推理、性能与长稳保持串行；未知专项先按独占处理。
- 模型准备的合并或复用只发生在外层编排与现有测试资源接口；固定来源、revision、大小、摘要和链接检查保留，各执行副本与合成资料仍属于本轮系统临时目录。不能修改真实用户资料、现用模型、索引或凭据，也不能用 Mock 替代本来要求真实进程/推理的检查。
- 20 轮面试、600 秒双路音频及五档缩放矩阵保持原范围；不能缩短时长、放宽断言、吞掉失败、只移除入口却留下弃用脚本，或将 Windows 结果作为 Mac 原生验收成绩。

### RAG 的明确限制

1. **RAG 功能与 0.6.7 完全保持一致。** 包括模型及权重、tokenizer/嵌入配置、切分与索引格式、候选与回取数量、评分/排序/来源选择、阈值、检索策略、问题/上下文处理、证据预算、超时及取消语义。本次不包含 RAG 功能更新或召回率优化，不保留测试期间的 RAG 探索性修改。
2. **只验功能调用链。** 使用合成资料，在面试中选择知识库并提交问题，核对 UI/preload/IPC/main、`RagChatService`、`KnowledgeHost`、知识库进程与检索结果进入生成请求的链路；同时覆盖未选库、选库隔离、资料缺失/不可用、异常与取消、结束/重开后的资源释放。沿用现有 `profile-ui`、`rag-ui`、`rag-core`、`knowledge-host` 及对应单测的职责，不引入真实账户或用户资料。
3. **测试流程优化不能变成 RAG 调参。** RAG 专项脚本、固定输入和断言沿用 0.6.7；允许调整它们外层的执行次序与重复资源准备，但不能改变生产 RAG 代码、模型、权重、阈值、候选池、检索策略或上下文规则。不能为了跑分增加词表、换模型、改标签或降低门槛。
4. **扩展语义研究不是本次发布目标。** 不把旧口语、公开题或迁移集合的召回率审计扩展成本轮优化任务，也不将“全部语义题命中”设为新增验收目标。召回率是测量结果；相同资料、索引、模型与输入下应保持 0.6.7 原有召回行为，不以不同测试条件下的百分比替代一致性核对。
5. **功能调用无问题就原样交付。** Mac 本机对照 0.6.7 产品源码与包内相关模块、模型目录元数据，确认无 RAG 差异。Windows 包内模块对照的方法只提供接续参考，Mac 需使用本机 0.6.7 签名基线与当前构建自行核对。发现调用链问题先定位环境或夹具并报告具体原因，不擅自扩大为检索算法或权重调整。
