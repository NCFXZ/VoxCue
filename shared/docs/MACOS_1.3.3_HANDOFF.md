# VoxCue 1.3.2 → 1.3.3：双端改动与 Mac 逐项验收

本次功能和界面范围同时适用于 Windows、macOS。共享实现位于 `shared/`；平台原生执行、签名和发行各自在本机完成。本文供 Mac 逐项核对，不将 Windows 的验证代称为 Mac 已验收。Windows 上保持 `macos/` 全树只读；Mac 接续后先读取根 `PROGRESS.md`，运行工作区同步，再构建本机应用。

版本唯一来源为 `shared/package.json` 的 `1.3.3`。Windows Store 身份版本为 `2.3.3.0`；Mac 不提交微软商店。保留既有固定 Mac 签名、更新签名、凭据助手和恢复原件，不生成新身份，不改依赖或模型版本。

Windows 1.3.3 已发布到 [GitHub](https://github.com/NCFXZ/VoxCue/releases/tag/v1.3.3) 和 [CNB](https://cnb.cool/voxcue-release/voxcue-release/-/releases/tag/v1.3.3)，CNB 匿名客户端索引已更新。微软商店 2.3.3.0 已提交 Submission 12，当前认证中。Mac 接续拉取 `main`，完成下列图标、原生差分、签名及本机验收后追加 Mac 资产；保留已发布的 Windows 文件和 `v1.3.3` 标签。

| 编号 | 1.3.3 改动 | Mac 逐项操作与预期 |
| --- | --- | --- |
| A01 | API 密钥目录仅保留 OpenAI、DeepSeek；账号授权保留 ChatGPT、GitHub Copilot。 | 检查两种登录方式及模型目录，没有已退役服务入口。分别连接、禁用、重新启用，不影响 VoxCue 主账户。 |

| A03 | 面试准备按实际模型能力启用网页搜索；实时面试保持关闭网页搜索。 | 准备聊天分别检查 ChatGPT、Copilot、OpenAI、DeepSeek 的支持模型；开场后同样问题不能触发面试网页工具。 |
| A04 | DeepSeek 搜索、读取网页、页内查找及回答活动按实际事件展示。 | 核对工具活动、公开查询词和地址；失败明确结束，不残留“进行中”，多事件不重复创建同一活动。 |
| A05 | 引用仅来自服务实际返回的结构化来源。 | 点击引用检查实际网页；没有来源时不虚构引用，不展示原始推理、签名或任意工具参数。 |
| A06 | 搜索、检索和生成阶段分别计时，本地检索只保留一条活动。 | 搜索不计作思考；停止、失败后阶段文字与计时结束；具体检索失败原因保留。 |
| A07 | DeepSeek 准备聊天使用文本意图标记及末尾 `<profile_proposal>`，不启用服务端 JSON 模式。 | 普通聊天不出现协议标记；要求修改资料时正文正常流式显示，提案生成中可打开只读预览。 |
| A08 | 缺失、矛盾、不完整或未实际改变资料的提案，通过同一模型、不带工具的短请求恢复。 | 分别制造这些响应；正文和已取得的搜索结果保留。补问失败明确报错，不伪称保存或把失败当成功。空白回答才整段重试。 |
| A09 | V4 Pro 可用 Responses 最终正文补齐缺失的增量。 | 模拟只有最终正文及中途停止；正文不丢失、不重复，不在取消后迟到写回。真实服务流协议另行复验。 |
| A10 | 共用提案校验可纠正错层级的 `skillScope`、来源清单和可修复的技能 id。 | 已有同名技能沿用 id；新技能不撞 id。未知字段、空正文、超限、重复 id 等错误仍按具体字段或技能报错，不放宽内容约束。 |
| A11 | ChatGPT、Copilot、OpenAI 保留原有结构化资料协议；Copilot 提案错误不再误报网络或登录失败。 | 三个服务分别生成、预览、勾选保存和保留原资料；仅保存选中项，其他资料不变。 |
| A12 | 发送新消息时，当前对话尚未处理的已完成提案自动按“保留原资料”处理。 | 旧卡片不可再保存，实际资料不变，状态重启后保留并进入下一轮上下文。空消息、发送前校验失败、重试回答和其他对话不受影响。 |
| A13 | 停用服务的旧选择按未连接处理，旧历史回答使用“未知模型”身份。 | 使用合成旧资料升级：正文、附件和记录仍在，不能因旧选择自动启用其他服务。 |
| A14 | 清理固定名称的已退役 API 密钥文件与专用资源。 | 仅在隔离合成账号中构造旧文件验证；保留现用服务及其他文件。Mac 原生凭据和路径边界本机核对，不读取真实密钥材料。 |
| A15 | AI 账号授权的启用状态和账号身份分别保存，可查看未启用账号的额度。 | 禁用后仍保留已登录身份；只展开额度不切换当前服务。切换主账号、退出和迟到请求不能把旧结果写入新账号。 |
| A16 | 账号额度请求按服务分别管理；真实零额度与未知额度分开。 | 双账号连接后分别刷新、失败、取消；零值正常显示，未知值不伪装成零，禁用服务不能发起聊天。 |

## 三、公告配置与安全边界

| 编号 | 改动 | Mac 逐项操作与预期 |
| --- | --- | --- |
| N01 | 固定匿名读取官网 `/app/announcements.json`。 | 官网发布有效 JSON 后启动和回到前台检查；不要求额外登录，不从其他地址或本地模拟内容兜底。配置部署说明见 [ANNOUNCEMENTS.md](ANNOUNCEMENTS.md)。 |
| N02 | 标题、副标题和可选按钮支持普通字符串或中英文对象。 | 切换语言后文案与网页地址匹配；对象缺少任一语言时明确拒绝无效配置。 |
| N03 | 版本筛选支持全部、低于、高于、指定版本。 | 分别验证 `all`、`lt`、`gt`、`eq`，比较三段数字；边界版本不误包含，构建后缀不改变结果。 |
| N04 | 支持全部、已登录主账户、未登录本地账户。 | 切换 VoxCue 主账户状态检查；ChatGPT、Copilot 或 API 是否登录不参与该筛选。 |
| N05 | 必填带时区过期时间，到期运行中也撤下。 | 测 UTC 与时区偏移、即将过期、已过期；关闭窗口或刷新不应延长公告有效期。 |
| N06 | 同一公告累计三次 X 后不再显示；独立“不再显示”立即生效。 | 重启累计，ID 相互独立，账号分区不串用，不跨设备同步；存储失败保留可重试提示。 |
| N07 | 可选按钮只打开 HTTPS 网页或进入白名单页面。 | 检查客户端设置定位和个人信息入口；不执行任意命令、不自动修改设置、不包含多步骤教学；拒绝脚本、文件地址和含账号密码的 URL。 |
| N08 | 限制公告数、长度、响应大小、超时与缓存。 | 最多 20 条、64 KiB、8 秒；10 分钟成功缓存与定期刷新。超限、重复 ID、无效字段、失败与退出取消不阻塞聊天，不产生模拟公告。 |

## 四、下载渠道、增量更新与发行

| D07 | 两个渠道保留完全相同的原始文件名、签名和摘要。 | Mac ZIP、DMG、签名清单及新增差分资产同步 GitHub `NCFXZ/VoxCue`、CNB `voxcue-release/voxcue-release`；不要重新打包镜像文件。保留 Windows 已发资产。 |
| D08 | 资产完整、匿名读取和摘要验证后才更新公开版本索引。 | 合并而非覆盖其他平台及历史记录；Mac 资产尚未完整时不能把该平台标成就绪。只发布正式 1.3.3，不重建已删除的测试版条目。 |
| D09 | 本地组件也按 IP 分流并同步镜像。 | 知识库索引、轻量语音识别、Qwen ASR、Q8_0 对齐模型及各平台运行时/分卷；使用现用固定 SHA256 与许可证，不能只镜像安装包。 |
| D10 | CNB 不上传应用源码。 | 仅附件、公开索引和必要发布配置；源代码、许可证链接指向主项目对应版本。复制完成后移除临时 `.cnb.yml`，避免重复搬运大文件。 |
