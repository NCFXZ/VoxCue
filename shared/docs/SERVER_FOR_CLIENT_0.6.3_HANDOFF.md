# 为客户端0.6.3适配服务端：逐项更新与实现交接

> 历史0.6.3交接：本文记录已发布客户端的固定v1行为。用户已确认独立服务端统一schema 2，不兼容旧统计客户端；Windows/Mac下一版另行适配，当前服务端契约见独立VoxCue-server/CLIENT_TELEMETRY.md。独立服务端0.5.3/schema9现已按后续授权部署，完整接口及适配见[服务端统计契约](https://github.com/NCFXZ/VoxCue-server/blob/main/CLIENT_TELEMETRY.md)和[部署文档](https://github.com/NCFXZ/VoxCue-server/blob/main/OPERATIONS.md)。下文保留历史0.6.3行为/交接，不作为当前兼容范围或部署授权，也不表示0.6.3已经适配。

2026-10-30追加：当前客户端工作区已按后续授权适配v2，详见[当前客户端协议](CLIENT_TELEMETRY.md)；目标版本已按后续授权更新为0.6.5，验收和发行状态见PROGRESS。此历史S/M清单不作为本轮修改服务端的授权，独立服务端保持只读。

此文描述**待实现的服务端更新**。本轮Mac只改客户端及交接，没有修改/部署服务端，没有执行其迁移或后端套件。固定参考为独立`NCFXZ/VoxCue-server`的0.5.2提交`472541cc80c77439f02c45d0bf0aed913b036134`。客户端版本0.6.3与服务端版本独立，不能把服务端默认改成0.6.3。

当前客户端所需能力已列于[统计协议v1](CLIENT_TELEMETRY.md)，包含完整类型、传输与26项口径；对应[Windows客户端C001–C082](WINDOWS_0.6.3_HANDOFF.md)。后续Windows Codex需在独立服务端仓库实现本页S/M清单；忽略的shared/server仅作原样客户端联调参考，不作为提交目标。保留远端后续提交/本机工作，不reset、强推或覆盖固定身份。

## 此轮客户端变化对服务端的影响

- 跳过登录与本地账户完全在客户端，不创建匿名云用户/会话，不授予同步、容量、账号注销权限；AI授权仍独立。既有账号、密码、验证码和同步协议无需为跳过登录放宽。
- 独立导出沿用本机归档，不新增服务端导出接口；云账号导出继续检查未恢复数据。本地导出不连云。移除注销弹窗两句说明不改变0.5.2后台最少注销记录和清理语义。
- 新增低信任匿名统计入口；本地账户与登录账户都可提交。客户端当前遇到404/405/501会暂存并退避24小时，现有服务端不支持它是预期，不应把这描述成后台统计已上线。
- 更新、模型、反馈链接仍使用GitHub，不因账号服务失效而关闭本地使用。服务器换机/域名迁移仍未实施；后续优先保留同origin与固定身份，不顺带改账号/更新信任根。

## 服务端逐项实施清单

| ID | 待新增/调整 | 交付与验证要求 |
|---|---|---|
| S001 | 盘点独立仓库现状并保留0.5.2后续工作。 | 比较固定参考与实际HEAD，保留当前用户/云资料/schema v5/管理员/邮件/DNS/TLS/对象存储身份。 |
| S002 | 定义统计domain/store/HTTP/admin职责。 | 不把收集、聚合和管理页写成巨型路由，不反向耦合账号和AI授权；不新增无消费者的框架或依赖。 |
| S003 | 新增POST /v1/telemetry/events。 | 同一账号服务origin，允许无登录请求；不能通过此端点获得账号/同步权限。兼容0.6.2旧客户端。 |
| S004 | v1信封白名单。 | schemaVersion、installationId、runId、sentAt、events、health；类型见客户端contracts/telemetry.ts，拒绝多余内容/身份属性。 |
| S005 | 事件公共字段白名单。 | id、installationId、firstSeenAt、runId、occurredAt、version、platform、accountMode、可选userId及data；UUID/时间/版本/模式组合严格校验。事件installationId匹配信封；补传事件的runId/身份可来自旧进程或切换前，不能强制等于当前批次。 |
| S006 | data判别联合与固定枚举。 | 逐种支持app_ready、account_entry、feature、interview_attempt/started/progress/ended、ai_request；不接受任意JSON扩展、错误原文或正文。 |
| S007 | 请求大小/并发/速率限制。 | 每批最多50条，建议HTTP正文≤128KiB；有界读/超时/并发/排队，按IP和安装ID限频，禁止无界内存或数据库积压。返回有界Retry-After。 |
| S008 | 匿名数据隔离。 | 不给本地账户造CloudUser/token/session，不复用AI令牌。不把客户端声明的userId当作身份认证、权限或计费依据。 |
| S009 | 登录关联与低信任维度。 | 校验ID形状及账号存在性/注销状态；客户端声明与服务端已认证注册/登录记录分开。需要新增证明时显式版本化并与客户端兼容，不悄悄要求现有v1必须登录。 |
| S010 | 账号状态不被统计请求影响。 | 统计错误不注销会话、不消耗验证码、不改变同步容量。注册/登录的权威计数从既有成功事务获取。 |
| S011 | 数据库迁移新增统计存储。 | 使用既有仓库下一schema版本和事务机制，仅owner临时数据库执行；升级失败回滚，旧用户/云原件不删除。 |
| S012 | 持久化事件与幂等。 | event.id唯一，同ID同内容重试返回同确认；同ID不同内容冲突不能覆盖原记录。事件入库和回执依据同一提交结果。 |
| S013 | 明确回执协议。 | 仅已持久提交的本批ID进入acceptedIds；schemaVersion=1；不发未知/重复ID。不能先返回200再异步丢弃。 |
| S014 | 支持部分回执。 | 已提交有效子集可独立确认，其余留给客户端；全部拒绝时返回明确有界错误，不伪造接收成功。 |
| S015 | 支持空事件健康批次。 | events=[]且有效health时允许acceptedIds=[]，持久化健康快照；不依赖持续空心跳。 |
| S016 | 时间及迟到事件。 | Unix毫秒、统一配置统计时区；按occurredAt归档，sentAt/接收时间保留作延迟诊断，迟到补记不能变成今日新增。时钟偏差/异常未来时间单独标记。 |
| S017 | 安装与账号双视图。 | 整体按installationId，账户视图按userId，本地按安装；同安装两种模式取并集，不能把分项简单相加。 |
| S018 | 首见与新老定义。 | firstSeenAt是首次统计标识时间，不是可信安装时间；userCreatedAt是账号注册时间。区分升级旧用户首次上报，不能宣传精确自然人数。 |
| S019 | 启动与主动使用区分。 | app_ready按runId去重；仅启动/登录不算DAU，feature才算实际使用；导入/编辑/查看/聊天/面试/导出保持分类。 |
| S020 | 注册/恢复/本地进入区分。 | account_entry.method四种分别保留；local不增注册，restore不伪称主动登录；累计注册包含既有成功注册及最少注销记录，重新注册的新UUID为新注册。 |
| S021 | 面试尝试与成功开始区分。 | attempt与started同interviewId关联；权限/模型/设备失败不算开始，恢复运行不重复增加已开始场次。 |
| S022 | 绝对快照更新。 | 每场只采最新sequence的activeMs/计数，旧批次迟到不回退，不把progress/ended的累计值相加。 |
| S023 | 有效面试计算。 | activeMs≥120000且3段有效终稿/1次人工提问/1次成功回答任一成立；校验客户端effective与数值一致，不把它视为真实招聘证明。 |
| S024 | 正常结束与故障。 | 保存成功completed；failed/interrupted区分，保留preflight/model/permission/audio/window/storage/process固定环节。进行中场次不进完成率分母。 |
| S025 | AI成功/失败/取消及延迟。 | 按随机requestId去重，chat/interview分组；重试仍同一用户请求，cancelled不混入失败率；成功样本firstAnswerMs取P50/P95。 |
| S026 | 活跃/留存/首次转化cohort。 | 日活、滚动7/30日活；首次有效面试7日窗口，次日/第7日回访；未成熟样本不能当作0留存。 |
| S027 | 本地转注册。 | 首次local后7日内register且服务端注册记录成立；登录已有账户不计转注册。同安装模式切换不重复计总活跃。 |
| S028 | 上报健康差分。 | health.counterId范围内累计attempts/failures取增量，latest pendingEvents/oldestPendingAt用最新sentAt快照；counterId变更不能产生负增量或重复累加。 |
| S029 | 管理页核心卡片。 | 累计注册、今日活跃、今日面试使用数、有效场次、面试总时长、新增使用安装数、首次有效转化、7日留存；可筛平台/版本/模式。 |
| S030 | 管理页趋势与详情。 | 完整26项及登录方式、新老、功能、时长/延迟、故障环节；显示单位、时间范围、统计时区、迟到/新鲜度和分母。 |
| S031 | 管理访问保护。 | 复用现有管理员/二次验证/CSRF/最小权限，统计查询仅授权管理端，不新增匿名用户列表/邮箱/ID枚举接口。 |
| S032 | 隐私与保留/清理。 | 原始事件有限TTL/容量、聚合长期策略单列；不存正文/音频/文件/截图/邮箱或长期原始IP。注销/禁用用户的关联与迟到事件策略明确，不复活已注销账号/原件。 |
| S033 | 快照/备份/恢复与迁移同步。 | 新表、索引、聚合状态、幂等游标和健康counter纳入既有一致性机制；恢复后不重复计数，历史schema可升级，版本不混写。 |
| S034 | 背压/对抗/性能。 | 重复/乱序/并发/断流/超量/坏字段/时钟回退/恶意ID/存储满/超时、1000次重试和有界资源；只用合成数据，不放宽阈值。 |
| S035 | 新旧客户端真实隔离联调。 | Windows0.6.3登录/本地两模式→真实临时HTTP服务→后台26项；离线恢复和重复回执、部分确认、空健康批次逐项实测；0.6.2认证/同步仍正常。 |
| S036 | 源码交付与上线边界。 | 客户端/独立服务端分仓审计并按当前授权正常提交推送；不把shared/server进客户端Git/包。此提示词不授权生产迁移、部署、重启、真实管理员/邮件/云权限操作。 |

## 26项管理指标逐项清单

| ID | 指标 | 关键规则 |
|---|---|---|
| M001 | 累计注册人数 | 服务端成功注册记录，含最少注销登记的历史注册；不从local或客户端事件重复加人数。 |
| M002 | 启动安装数 | app_ready的安装去重。 |
| M003 | 启动次数 | app_ready按runId去重。 |
| M004 | 登录账户数 | 成功login/register/restore按用户去重，方式分组；声明和权威来源区别标注。 |
| M005 | 日活 | 当日实际feature的安装/账户去重。 |
| M006 | 周活 | 最近7日实际feature去重。 |
| M007 | 月活 | 最近30日实际feature去重。 |
| M008 | 功能使用率 | 使用该feature的活跃数÷同期间活跃总数，非精确点击次数。 |
| M009 | 今日面试使用数 | 当日started的安装/账户去重。 |
| M010 | 成功开始场次 | started按interviewId去重。 |
| M011 | 有效面试使用数 | 达到有效阈值的安装/账户去重。 |
| M012 | 有效场次 | effective的interviewId去重，中断前已达标也保留。 |
| M013 | 面试总时长 | 每场最新sequence的activeMs之和，扣除客户端暂停/休眠，不能累加快照。 |
| M014 | 时长分布 | 每场最新activeMs分布，可筛有效场次。 |
| M015 | 完成率 | completed÷已终结且成功started的场次。 |
| M016 | 失败率 | failed/interrupted÷有终态的尝试，含启动失败，进行中不入分母。 |
| M017 | 新增使用安装数 | firstSeenAt归档的新安装ID，表示首次统计到，不等于下载安装人数。 |
| M018 | 首次有效面试转化率 | 同批新增安装7日内有效面试比例，区分成熟窗口。 |
| M019 | 次日留存率 | 首次统计后次日有实际操作。 |
| M020 | 7日留存率 | 首次统计后第7日有实际操作。 |
| M021 | 本地转注册率 | 首次local后7日内完成新注册，排除已有账号登录。 |
| M022 | AI回答成功率 | success÷(success+failure)，cancelled单列。 |
| M023 | 回答等待时间 | 成功请求的首段可见回答耗时P50/P95。 |
| M024 | 上报失败率 | 同counterId的累计失败/尝试增量；不是把快照相加。 |
| M025 | 待补传事件数 | 每个安装最新health.pendingEvents，排空健康批次可回0。 |
| M026 | 最早待补传等待时长 | 最新sentAt减oldestPendingAt，空队列为0，不能在长期离线时无限推大旧快照。 |

计数单位必须可见：整体/本地是安装数，账户视图才是账户数；本地和登录分项可重叠。所有指标先在同一合成数据集手工算期望值，再验证聚合/API/管理UI一致。零分母显示“暂无数据”，不能显示虚假的0%成功或100%留存。

## 接口示例与验证顺序

正式请求形状以客户端`contracts/telemetry.ts`及[协议v1](CLIENT_TELEMETRY.md)为准，不复制另一个漂移的事件定义。服务端实现自己的校验层并用共享样例测试一致性；服务端不能依赖客户端工作区运行。

```json
{"schemaVersion":1,"acceptedIds":["a0000000-0000-4000-8000-000000000001"]}
```

先实现迁移/校验/事务/幂等和聚合单测，再真实临时HTTP联调，最后管理UI与安全/背压/恢复完整测试。仅合成临时数据库/内存邮件/自有loopback，GUI串行；缺环境准确标待验，不用Mock结果冒充实际HTTP或Windows原生。测试结果只终端/对话，不把数据库、凭据、截图、模型或执行报告提交。
