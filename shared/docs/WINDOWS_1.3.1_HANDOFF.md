# Windows 1.3.1 更新与逐项验收

本清单比较 Windows 正式源码 `v1.3.0`（`669c44a`）与 1.3.1 共享代码及 macOS 实现。配套账号服务为已发布的 0.6.1（`3440a25`）。表中每个编号均可在 Windows 端独立记录结果。对照既有功能可查 [Windows 1.3.0 交接](WINDOWS_1.3.0_HANDOFF.md) 和 [1.3.0 桌面更新范围](../../docs/1.3.0_MACOS_UPDATE.md)。

准备两个由测试者控制的临时账号，用同一账号的两份隔离设备资料制造冲突。准备一份简历、两场面试、一张共用截图、两张专属截图及两个各自包含多份文档的知识库。跨设备用例需能独立控制每端的编辑、网络与同步时机。使用合成资料及公开的测试音频，保持正式账号和真实资料隔离。

| 09 | 在冲突窗口打开期间修改另一端版本，然后提交原选择。另一次提交多个独立项目并模拟其中一个传输失败 | 过期决定失效，界面要求重新选择。已成功的项目可完成，未成功或新产生的冲突仍可处理。刷新或再次点击不会将过期选择覆盖到新资料。 |
| 10 | 在长任务处理中退出测试账号并登录另一个合成账号，随后返回原账号 | 两个账号各自显示自己的云状态、冲突和资料。迟到的异步结果不能写入新账号。返回后按当前云端与本机版本重新核对。 |

## 版本核对、删除和异常恢复

| 编号 | 在 Windows 上操作 | 预期表现 |
| --- | --- | --- |
| 11 | 准备两端内容相同的资料、从旧封包恢复的面试及确实改成两个版本的资料，各做一次同步 | 已能核实相同的版本自动收敛。无截图且已相同的面试可清除中断遗留的决定。真正不同的两份内容保留待选。 |
| 12 | 在同一知识库分别加入本地独有、云端独有和同名不同内容的文档，再分别演练保留整库云端或本地 | 库信息与成员按所选版本处理，另一端独有的原件也按整库选择核对。其他知识库可正常打开，且只有选中的库发生替换。 |
| 13 | 选择一端已确实删除的库，再用另一组资料模拟获取云清单失败或云端文件校验失败 | 前一种情况先提示选择该端会移除另一端副本。读取失败、封包损坏或版本不明时保留可用原件，错误或冲突仍可重试。 |
| 14 | 在选择后、写回前向云库加入文件或将文件移至另一库 | 客户端重查版本及库成员。迟到的上传、删除或整库选择不能覆盖新成员，遇到冲突的库可重新核对。 |
| 15 | 删除含专属及共用截图的一场云端面试，用另一场打开共用截图 | 成功按修订删除记录后，清理这场记录专属的截图。检查时已被其他记录引用的截图保留，另一场仍可打开。 |
| 16 | 在删除云面试的记录请求和后续截图清理两个阶段分别中断，然后重启 | 记录删除失败时原图保留。记录已删而清理中断时可继续清理，再次检查有其他引用的图片。 |
| 17 | 上传或下载期间关闭对应类别同步，再将所有类别关闭，随后刷新容量 | 关闭的类别停止后续自动传输及本地写回。全部关闭时跳过周期性完整清单扫描，刷新容量仍可获取用量。 |
| 18 | 用较多历史记录、知识库和图片启动，等待空闲轮询，再编辑一条资料 | 同一轮复用资料目录快照。未改变的记录和图片不逐一读取正文，编辑项仍会同步。前台导航和输入保持响应。 |

截图删除还有一项跨设备时间窗口。账号服务 0.6.1 删除图片时核对图片修订。如果另一台设备恰好在客户端最后一次检查引用后才新增引用，原图仍可能被删除。第 15、16 项验收覆盖客户端已能核对的引用。[同步回归](../test/unit/cloud-sync.test.ts) · [服务端实现](https://github.com/NCFXZ/VoxCue-server/blob/3440a2517ad3e4d2ee486c76023d229a0ec17fa8/src/backups.ts#L505-L515)

## 资料迁移、知识库和检索

| 编号 | 在 Windows 上操作 | 预期表现 |
| --- | --- | --- |
| 19 | 迁移较多来源资料，选择来源后单击“下一步”，再尝试重复提交 | 等待预览或恢复清理时按钮显示加载图标，重复点击只产生一次操作。出现错误后可重新选择来源。 |
| 20 | 用隔离夹具在目标已保存、来源尚未清理时中断。重开迁移并选择同一来源 | 客户端核对回执并继续清理已迁移项。完成后显示来源已清理。没有其他可迁资料时可直接关闭。目标资料仅有一份，来源中未选的资料仍在。 |
| 21 | 迁移个人信息的多个字段、简历及多场旧面试，其中一场包含内嵌预览图，另一场使用“「知识库名」面试名”组成的长标题 | 个人信息按一个来源资源计数，预览按目录读取面试标题。合法组合标题保留原文，正文按需读取并核对大小。清理逐场核对图片修订，已修改的原图保留。 |
| 22 | 用合成回执和封包测试单场 4,095 张截图和超出上限的输入 | 迁移回执及面试封包使用相同上限，边界内可处理。超出范围应被拒绝，仍可从来源恢复。 |
| 23 | 迁出一个含正文、搜索索引和待恢复版本的知识库，重开来源并搜索，检查另一个知识库 | 迁出的库清理自己的索引正文和恢复记录，重启后不会再从旧索引搜到已迁出的资料。未迁出的库可继续搜索。 |
| 24 | 一次导入多份文档，部分先完成，其余继续索引，离开资料卡再返回 | 库卡片汇总整批文档的索引进度。索引结束后可搜索到各份文档，不会因单份先完成而提前显示整批完成。 |
| 25 | 通过迁移和从云恢复分别导入一个多文档库，在批次中途及完成后搜索 | 全文索引按库分批发布。写入新快照期间可查询已提交内容，提交后可检索新内容。中断重开后使用完整的已提交版本。 |
| 26 | 导入含独特短语的合成原件，完成索引，在准备聊天检索并核对来源。修改、停用或删除资料后重试 | 命中启用的当前资料，引用能对应回原件，更新后不再引用失效版本。本项只验收导入、索引、检索、引用和失效处理。沿用现有模型和阈值，排除曾用于训练其他模型的数据集。 |

第 26 项分两步执行。用界面夹具检查导入和重启持久化，再用真实模型和 LanceDB 的核心夹具检查关键词、向量及混合检索，打开引用，替换文档后核对旧引用失效，再删除文档并搜索。核心夹具每次生成新的合成原件，取消索引批次和跨库查询也在此覆盖。[迁移选择](../src/components/AccountMigrationPanel.tsx) · [来源清理](../test/unit/profile-import-removal.test.ts) · [迁移计划](../test/unit/account-import-plan.test.ts) · [知识库批处理](../test/unit/knowledge-core.test.ts) · [RAG 界面夹具](../test/scripts/rag-ui-smoke.mjs) · [RAG 核心夹具](../test/scripts/rag-core-smoke.mjs)

Windows 1.3.0 和本版共用 E5 q8 的固定修订 `761b726`。与 `v1.3.0` 比较，嵌入、检索相关性阈值、证据筛选及上下文预算的源码一致。[模型和文件摘要](../scripts/rag-model.json) · [检索实现](../electron/backend/knowledge/grounding.ts) · [证据筛选](../electron/application/ragSelection.ts)
