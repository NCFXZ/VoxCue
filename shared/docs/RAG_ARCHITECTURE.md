# VoxCue LanceDB RAG 架构

VoxCue 使用本地知识库为准备聊天和实时面试提供可核实的参考资料。

## 检索与证据

准备聊天和已确认的面试问题共用 `RagChatService → KnowledgeHost → utilityProcess → KnowledgeService`。`knowledgeBaseId` 为 null 或省略时不访问知识端口、模型和状态；明确选择时只搜索该库。记录标题继续使用原始 Provider。Renderer 不加载数据库或模型。

生成路径采用原 B+ 的正文与词面融合。按主问聚合同一问答组的分块，分别取正文余弦和 BM25 的最大值。词面分除以本次同库最高词面分，以 0.05 的权重加入正文余弦。独立问题要求排名第一组的当前问题正文余弦达到 0.8811，再按融合顺序回取最多六组。追问沿用原 B+ 的准入规则，短问或追问线索可以绕过该门槛，因此即使资料不足也可能返回证据。知识库管理使用原有 keyword、vector、hybrid 和全文索引。

相对原 B+，只改变追问如何使用前文。系统取最近三个可信问题，比较当前问题和各题的语义相似度。普通追问给最近一题加 0.06，出现“回到”“之前那个”“最开始”等回指时取消这项加分。只选一条前文，将它和当前问题的检索分按 1∶1 相加。模型沿用 E5-small，没有单独编码标题。

`KnowledgeHit.itemId` 仍是根条目，`matchedItemId` 保留实际匹配。新路径通过`matchedItemIds`提供同一根下最多5个依赖追问，先保留匹配项，再补齐父问题关联内容，避免有故障描述却丢掉恢复步骤。所有子条目必须同根、同文档、同库和同revision；跨根、重复或超过上限拒绝。`getItem`仍返回完整根与关联追问，证据节选明确标记，48KB预算保持。旧端口无新元数据时保留旧的单匹配/完整内容兼容。

15 秒是整次检索期限，48,000 UTF-8 字节是证据预算，均不放宽。超预算整项省略、同项/同内容去重，个人经历仍优先简历。参考数据是附于当前问题的不可信 JSON，不改写原问题/历史，不上传整库，不把文档指令提升为系统规则。仅明确可用性故障允许 complete/partial/unavailable 回退；参数、身份、版本、完整性、模型未就绪与取消仍停止。无相关资料属于正常空结果，继续通用回答。

## 面试重试与索引调度

面试最多四次生成尝试，间隔 500/1000/2000ms。集中类型策略仅重试受控网络中断、响应等待/空闲超时、空响应及明确 502/503/504；400/401/403/429、其他未批准状态、额度/权限/参数/模型/配置/完整性和未知错误不猜测文案重试。主动取消立即停止等待和迟到事件。

`beginRequest` 作用域仅在同一题重试期间保留成功且完整的非空证据。身份包含请求、有效检索词、可信前文、模型配置、附件摘要和选择策略版本。每次重试核对所选库的已提交文档/revision 令牌。删除、停用、更新或请求改变使其失效。部分/失败结果不缓存。成功、最终失败、取消和结束释放。证据只在该次请求内复用。

KnowledgeCoordinator 在主进程拒绝面试期间新增导入/重建；原件不会因此删除。已有长索引仍由原串行核心完成，选库开场检查及实际打开再次拒绝在其后排队，提示结束索引后重试；无库面试不等待知识核心。保留数据库串行一致性，不抢占正在写入的索引。

面试主进程收集已提交问题和面试官转写终稿，每条前文至多 200 个字符，同一问句的相邻转写和提交只占一项。AI 建议、面试者回答和默认截图问题不进入检索前文，遇到转写间断、暂停或新场次即停止回溯。向知识进程分别传递当前原句和可信前文，生成请求继续使用原始问题、对话和附件。

## 存储与进程边界

检索进程按所选库的已提交快照计算 BM25 词频和正文余弦。中小库在内存中复用向量与词表，预计缓存超过 64 MiB 时改为逐批读取所选库的分块。近几次问句的向量只在进程内短暂复用，前文候选仍来自当前面试会话。

启动只打开目录指向的已发布表版本。读取文档时按目录核对条目数量、ID 和父子关系。单份正文损坏时仍可检索同库的其他来源，重导相同原件可修复损坏修订。正文缓存按磁盘字节计，上限 16 MiB。[索引读取](../electron/backend/knowledge/service.ts) · [正文与来源回归](../test/unit/knowledge-core.test.ts)

固定 multilingual-e5-small revision `761b726dd34fb83930e26aab4e9ac3899aa1fa78`，Q8 CPU、384 维、query/passage 前缀、mean pooling 和 L2 归一化。`qa-linked-v3` 支持 Markdown 加粗主问与追问标记，并保留原始文本和父子关系。索引按账户存储，原件保存在 IndexedDB。

数据库只写 userData。同一账户的每个知识库及简历有独立的索引目录、LanceDB 表、正文版本和恢复目录。更新先解析并写不可变 revision，用 mergeInsert 替换目标行并更新 ICU FTS，最后原子提交该库的 catalog。读者只打开已提交版本。原件备份失败拒绝覆盖。多个独立应用进程并发写同一目录仍未支持。

从共用索引表升级时，账户首次打开索引会先登记旧表、索引正文和恢复记录，再清理这些生成文件。清理直接处理索引文件目录，无需打开 LanceDB 历史版本。IndexedDB 原件、资料库和文档 ID 保留，启动核对按库从本地原件重新索引，沿用文件和知识库进度。已经发布的分库索引继续使用。中断后根据清单继续清理，并从实际已提交的分库目录补齐索引。重建后的索引版本和引用快照会更新。

本地或云账户打开后，先核对该账户的索引版本并清理已确认归属的旧表、旧正文和对应恢复记录。混合目录保留当前 v3 文档及其可用恢复版本。清理期间，涉及的文档在文件大小后同时显示「正在删除旧索引…」。清理成功后重新读取目录，检索组件就绪时按原有流程从 IndexedDB 原件重建缺失的索引。清理记录随目录持久化，进程中断后可在下次打开时继续。[启动核对](../src/stores/knowledgeIndex.ts) · [索引迁移](../electron/backend/knowledge/indexUpgrade.ts)

用户一次选中的同库文件可共用一次发布。写进程先预留本批文件名和可能需要的新表名。每份原件单独解析并写入暂存版本，全部就绪后建立一次 ICU 全文索引，最后切换目录。旧目录继续服务并发查询。回退时保留已经发布的版本，单份取消持有原请求标识，其他有效原件可按需重试。异常退出后仅由写进程检查本批清单，对照活动及备份目录回收未引用的专属暂存。已有表沿用原有版本恢复机制。[批次归属及回收](../electron/backend/knowledge/indexBatch.ts) · [真实模型与独立进程回归](../test/scripts/rag-core-smoke.mjs)

PDF/DOCX/Markdown/TXT 的既有解析、分页、Q&A 父子关系及辅助分块保持，模型按实际 tokenizer 检查长度。扫描 PDF 仍需 OCR，复杂表格/公式/阅读顺序没有新增保证。原件和知识库管理界面不因本轮更改。

确认整库删除后，客户端先保存待删任务并撤销目标库的索引请求。目标库的读写进程退出后，应用原子移走该库的独立目录，再清理其索引、历史正文、IndexedDB 原件及备份。其他库在各自的写进程内继续索引和提交。移走后中断时，下次启动根据待删任务继续清理。单文档删除与替换沿用该库内的索引恢复流程。此流程处理 VoxCue 管理的本机数据，用户导出的副本和云端各有生命周期。

## 本地来源与离线验证

后端可返回同库、文档、根/匹配条目、章节/页码、revision 和节选标记；受控 item 操作在读取前验证来源身份及当前版本。按用户最新范围不新增引用预览界面或更改聊天展示。

测试专用注入观察器提供原始 chunk/根 ID、候选/短名单、成功读取、过滤/预算/使用原因及耗时，不记录真实问题、原文、文件名或凭据。生产不装配观察器。`rag-validation-smoke.mjs` 在自有临时目录下载校验固定公开模型，以真实 E5/LanceDB 对照旧 Local 选择策略和新策略；夹具为 100 个可检查合成问题及 20 个留出问题，覆盖改写、不同项目、连续追问和无答案。比较候选池、召回、排名、证据精度、错误证据、误命中及本地暖态耗时，保护旧成功案例。结果仅终端，模型与数据库退出清理。

合成标签不是独立人工标注用户语料；本地准备/mock Provider 首段时间不是实际账户 TTFT。真实账户生成质量、真人语义准确率、复杂文件解析和 Windows 本机原生表现仍需相应环境验收。入口见 [测试说明](../test/README.md)。

补充口语审计入口 `rag-colloquial-smoke.mjs`：固定120个场景与19份合成资料，保留口语中的“咋办”“那它”“那你们”等表达，通过实际检索和证据边界区分召回遗漏、过滤遗漏、追问内容缺失及其他项目资料混入。含糊问题和相关但缺少具体事实的问题单列，不冒充普通已知答案。该审计不调整生产参数，也不调用真实生成模型；完成评估不等于准确率达标，结果仅终端/对话。

`rag-unseen-oral-smoke.mjs` 默认使用已知240题回归集；`--transfer` 使用冻结v6后另写的160题、16份新资料，增加长链口语追问、陌生项目、同文件近名项目、纠正、间断和无关问题。资料、所需事实、源码与编译后端均在运行前记录指纹，运行后核对。新集合查看结果后即成为已知评估集，不据其结果继续调参或宣称独立真人准确率。按用户最新要求，目标是足够支持常规面试，不追求全部命中；报告完整证据覆盖和项目污染、无关/含糊误注入，保留漏召回与误判。缺失具体事实即使有相关背景，也不能视为已取到答案；此处没有验证生成模型是否会拒绝编造。

公开200场景由`--public`运行，题目、事实与首次门槛保持，仅用于评估；夹具protocol记录首次v6基线，实际执行版本以运行时selection为准。v7以机制单测及既有开发兼容夹具完成修改并冻结后再评估该集，观察结果后不继续调整。随后另取Devinterview、Arialdo Martini和Karan Pratap Singh的公开题源整理172场景/16份资料，通过`--public-transfer`验证，并用冻结的修改前编译后端比较。同一人改写和标注的口语链及短笔记不能代替独立真人面试、完整长文档解析或真实生成答案验证；结果仅终端/对话。
