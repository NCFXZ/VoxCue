# Mac 0.5.11：ChatGPT 续期延迟修复与本机审查

日期：2026-10-25（Europe/London）。源码比较基线：`4f5e84189b4f3adc6dbc0ea0decb6ce4d1809872`。Windows 本轮结果见 [Windows 0.5.11 验收](WINDOWS_0.5.11_VERIFICATION.md)，可直接执行的接续提示词见 [Mac 审查提示词](MACOS_0.5.11_CODEX_PROMPT.md)。

Mac 接续结果见 [M01–M12 独立验收账本](MACOS_0.5.11_VERIFICATION.md)。Mac 三项资产已补入既有 v0.5.11，Windows 资产保持；当前 smoke 已将 Mac 子进程网络权限收窄到其自有停滞代理端口，仍禁止外网。新增 `macos/test/scripts/chatgpt-renewal-smoke.mjs` 验证旧强制续期与按需读取、临近过期/过期续期、失败、重复读取、退出和迟到结果；最终 ASAR 使用同一夹具核对实际解包的固定运行时。真实账户和 LLM 生成速度仍不属于合成认证实验结论。

## 用户反馈与问题范围

用户在 Windows 安装版和开发版均遇到 ChatGPT 启动/登录 loading 久、面试回答等待久、刷新账户额度慢；同机 GitHub Copilot 很快，Mac 未见同等延迟。该缺陷位于两端共用后端，所以原 Mac 版也包含重复强制续期逻辑；未观察到延迟不代表 Mac 没有该逻辑。

Windows 未访问真实 ChatGPT/Copilot 账户、凭据或资料进行联调，也没有进行同账户同网络的 Mac/Windows 对照。不能据此认定 Windows 系统、凭据保护机制或网络栈是唯一原因，亦不能将合成认证阶段耗时称为真实回答首字/完整回答耗时。

## 已确认根因与最终实现

入口为 `shared/electron/backend/chat/codexUsage.ts` 的 `access()`。原实现每次调用 `getAuthStatus` 都传 `{ includeToken: true, refreshToken: true }`。固定官方 Codex **0.164.0** 的实现会执行强制远端续期，即使当前凭据仍有效。启动恢复、模型目录、聊天/面试连接、本地用量读取及额度前后身份校验都消费同一方法，因而一次用户操作可能重复续期；续期还会使官方工作区路由缓存失效。

本次只将该 RPC 改为 `refreshToken: false`，交由官方运行时按其有效期/刷新策略按需续期。没有改为“永不续期”，没有延长令牌有效期、增加应用令牌缓存、绕过身份检查或增加明文存储。`managedAccess()` 仍拒绝过期/无效/非 ChatGPT 令牌，账户及工作区校验、取消、退出与迟到结果保护保持。

`limits()` 另传 `{ excludeResetCreditDetails: true }`，省去界面不使用的“重置额度凭证明细”请求。它不影响 `resetsAt` 等官方重置时间、5 小时/每周窗口、剩余百分比或套餐解析；不能把该参数理解为隐藏重置倒计时。

核对依据为固定版本官方源码：[账户 RPC](https://github.com/openai/codex/blob/rust-v0.164.0/codex-rs/app-server/src/request_processors/account_processor.rs)、[认证管理](https://github.com/openai/codex/blob/rust-v0.164.0/codex-rs/login/src/auth/manager.rs)、[工作区路由](https://github.com/openai/codex/blob/rust-v0.164.0/codex-rs/app-server/src/request_processors/account_processor/workspace_routing.rs)。审查时保留 0.164.0，不以新版本不同语义替代当前基线。

## Windows 已有复现证据

使用固定 Windows 原生运行时、独立临时目录、有效期内的合成令牌和仅接收不应答的本机代理，不访问真实凭据或远端服务：强制续期模式约 **15246ms** 超时；相同条件的按需模式冷启动约 **249ms** 成功；修复并重新构建后的原生回归约 **139ms** 成功。最终 0.5.11 Windows ASAR 加载真实解包运行时的同类检查约 **153ms** 成功，固定 Copilot stdio/ping 也通过。计时含进程启动，属于认证路径复现。

此前只用立即拒绝连接的代理，强制续期失败很快，官方进程仍可能返回有效缓存令牌，因而旧 smoke 没能暴露等待。本次测试改用停滞代理，并为有效会话交接加 5 秒截止；单元测试同时约束按需参数及不请求重置额度明细。

**交接时的 Mac 测试限制（已修正测试入口）：**原 smoke 通过 `sandbox-exec` 禁止子进程所有网络，连接可能立即被拒绝，不能把其“快速返回”单独称为 Mac 停滞网络负对照通过。接续实现仅允许隔离合成进程访问本次拥有的 loopback 代理端口，继续禁止任何外网，不使用系统真实 keychain 账户；新增原生夹具还明确检查外网和其他端口被拒绝。不得为测试便利放开生产权限或取消过期校验。
